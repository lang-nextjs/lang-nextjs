### Human Verification Required

#### 1. End-to-End Network Reconnect

**Test:** In a browser with DevTools, simulate going offline while a stream is active (DevTools > Network > Offline), then go back online.
**Expected:** The client automatically reconnects via the GET resume endpoint and the stream resumes without duplicating already-received content.
**Why human:** Real-time network behavior, browser DevTools interaction, and visual message deduplication cannot be verified programmatically.

#### 2. Page Visibility / Tab Switch Reconnect

**Test:** Start a stream, switch tabs, then switch back. Without calling `retry()` manually, no auto-reconnect occurs (expected per AI SDK bug #11865). When `retry()` is wired to the Page Visibility API, switching back triggers reconnection.
**Expected:** Manual `retry()` triggers reconnect; passive tab-switch does not (confirming known limitation is documented correctly).
**Why human:** Browser tab switching behavior requires live browser interaction.

#### 3. 409 Deduplication Under Concurrent Requests

**Test:** Submit two POST requests with the same `X-Resume-Id` value while `ENABLE_STREAM_RECONNECT=true`, concurrently (e.g., via two fetch calls in rapid succession).
**Expected:** First request streams normally; second request receives 409.
**Why human:** Race condition behavior under true concurrency requires a running server and load tool.
