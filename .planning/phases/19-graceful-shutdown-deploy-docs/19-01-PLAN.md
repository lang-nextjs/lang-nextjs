<constraints>
- ZERO new runtime dependencies — native Node `process` + `setTimeout`/Promise only. No EventEmitter subclass required; keep it a plain factory returning an object.
- Node-only, OPT-IN: importing the module MUST NOT register any signal listener. A listener is registered ONLY when the consumer calls `installSignalHandlers()` (or wires `process.on('SIGTERM', () => shutdown.dispose())` themselves). Tests MUST NOT leave SIGTERM listeners installed — use `process.removeAllListeners` in teardown or never call the auto-installer in unit tests.
- NO module-scope mutable state — all state (draining flag, activeStreams Set) lives inside the object returned by the factory (per-instance). Do NOT add a module-level singleton.
- Integrate with Phase 18: `shutdown.isDraining()` is the function consumers pass to `createReadinessProbe({ isDraining })`. Do NOT modify health.ts.
- dispose() MUST be idempotent (duplicate SIGTERM is ignored) and MUST always terminate via a safety timeout even if streams never release.
- IMPORTANT (testability of exit): do NOT hard-call `process.exit()` from inside the drain loop in a way that makes unit testing impossible. Make exit injectable: accept an optional `onExit?: (code: number) => void` in config (default `(code) => process.exit(code)`). Tests pass a spy; production uses the default. dispose() resolves after invoking onExit.
</constraints>

    API (factory returns an object — no class export required):
      createGracefulShutdown(config?: {
        drainTimeoutMs?: number;   // default 30000
        onExit?: (code: number) => void;  // default process.exit; injectable for tests
        logger?: (msg: string) => void;   // default console.warn/log; optional
      }) => {
        isDraining(): boolean;
        trackStream(streamId: string): void;
        releaseStream(streamId: string): void;
        activeCount(): number;
        dispose(): Promise<void>;
        installSignalHandlers(): () => void; // registers process.once SIGTERM+SIGINT -> dispose(); returns an uninstall fn
      }

    Cases (input -> expected):
      - new orchestrator -> isDraining() === false, activeCount() === 0
      - trackStream("a"); trackStream("b") -> activeCount() === 2
      - trackStream("a"); releaseStream("a") -> activeCount() === 0
      - duplicate trackStream("a") twice -> activeCount() === 1 (Set semantics)
      - dispose() called with 0 active streams -> isDraining() flips true, onExit(0) called, resolves promptly (no full-timeout wait)
      - dispose() with active streams that release during drain -> waits, then onExit(0) once activeCount hits 0 (use fake timers; release stream mid-wait)
      - dispose() with a stream that NEVER releases -> after drainTimeoutMs, onExit(1) called (safety timeout), promise resolves (no infinite hang)
      - dispose() called twice -> second call is a no-op (onExit invoked exactly once)
      - drainTimeoutMs is configurable (e.g. 50ms) and respected
      - READINESS INTEGRATION: createReadinessProbe({ isDraining: () => s.isDraining() }) returns {ready:true,status:"ok"} before dispose, and {ready:false,status:"draining"} after dispose() sets draining=true
      - installSignalHandlers() registers a SIGTERM listener (assert process.listenerCount('SIGTERM') increments); returned uninstall fn removes it (count returns to prior)
