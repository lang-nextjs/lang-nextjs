## Decisions Made

1. **LangGraph: live-capture** — FastAPI backend was running with OpenRouter API key; captured real frames via `docker compose exec -T backend python3` script calling `astream_events` directly (not via HTTP endpoint which already normalizes to AI SDK v6).

2. **LangChain: research-docs** — Django backend inspected, confirmed it also normalizes to AI SDK v6 before SSE output. No LangChain native SSE emitter exists in project. Fixture constructed from RESEARCH.md validated mappings.

3. **Real event field name is `event`** — `astream_events v2` returns `{"event": "on_chat_model_stream", ...}` not `{"type": "..."}`. RESEARCH.md used "type" as an informal shorthand in the mapping table. ADAPT-03 transform must check `event.event` field.

## Deviations from Plan

None - plan executed exactly as written. The plan explicitly anticipated the Django backend might already emit AI SDK v6 format and provided fallback instructions for constructing research-doc fixtures in that case.

## Issues Encountered

- FastAPI backend `/openapi.json` endpoint returned 404 (no FastAPI auto-docs mounted) — resolved by reading `main.py` directly to find the `/api/chat/stream` endpoint. Did not block execution.
- LangGraph `create_react_agent` emits many frames with empty `chunk.content` before actual tokens (initial prompt processing frames). Worked around by filtering for non-empty content in fixture selection.
