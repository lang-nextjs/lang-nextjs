<ai_sdk_v6_wire_format>
AI SDK v6 frame types that adapters must produce. The adapter output MUST match these shapes exactly — AI SDK v6 rejects extra or missing required fields.

| Frame type           | Required fields                                          | Optional fields          |
|----------------------|----------------------------------------------------------|--------------------------|
| text-delta           | type, delta (string)                                     | id                       |
| finish               | type, finishReason ("stop" | "length" | "tool-calls")   | usage                    |
| tool-input-start     | type, toolCallId (string), toolName (string)             | —                        |
| tool-input-delta     | type, toolCallId (string), delta (string, JSON partial)  | —                        |
| tool-input-available | type, toolCallId (string), toolName (string), input (object) | —                   |
| tool-output-available| type, toolCallId (string), output (string)               | —                        |
| data-*               | type (must start with "data-"), data (any)               | —                        |

Note: `id` on text-delta is optional. Frames with unrecognized `type` values are silently dropped by AI SDK v6 clients.
</ai_sdk_v6_wire_format>

    **Expected behaviors (adapt to actual fixture shapes):**

    **token frame → text-delta:**
    Input:  `{ raw: 'event: token\ndata: {"type":"token","text":"Hello"}' }` (or just the data line)
    Output: `{ raw: 'data: {"type":"text-delta","delta":"Hello"}' }`
    (text-delta requires: type + delta — see AI SDK v6 wire format table above)

    **message frame → finish (DESIGN INTENT — DROP DUPLICATED CONTENT):**
    IMPORTANT JSDoc clarification: LangChain message frames signal the end of the LLM response stream. The frame contains the accumulated response text in a `content` field. However, this text SHOULD NOT be re-emitted as a separate text-delta frame, because:
    1. AI SDK v6 stream accumulation already has all token fragments from earlier token frames
    2. Re-emitting the full text would duplicate content and cause double-counting in the client
    3. The message frame's semantic meaning is "end of response" (finish), not "here is new content"

    Design decision: When a message frame is received, emit ONLY the finish frame (type: finish, finishReason: stop) with NO content. Drop the accumulated text from the message frame (do not re-emit it as a text-delta).

    Input:  `{ raw: 'event: message\ndata: {"type":"message","content":[{"type":"text","text":"Hello world"}]}' }`
    Output: `{ raw: 'data: {"type":"finish","finishReason":"stop"}' }`
    (finish requires: type + finishReason — see AI SDK v6 wire format table above)

    **tool_call frame → tool-input-available:**
    Input:  `{ raw: 'event: tool_call\ndata: {"type":"tool_call","tool_name":"search","tool_input":{"query":"weather"}}' }`
    Output: `{ raw: 'data: {"type":"tool-input-available","toolCallId":"lc-search-0","toolName":"search","input":{"query":"weather"}}' }`
    (tool-input-available requires: type + toolCallId + toolName + input — see AI SDK v6 wire format table above)

    **error frame → drop:**
    Input:  `{ raw: 'event: error\ndata: {"type":"error","message":"..."}' }`
    Output: null (drop — error propagates via stream error, not as a forwarded frame)

    **[DONE] frame:**
    Input:  `{ raw: 'data: [DONE]' }`
    Output: `{ raw: 'data: [DONE]' }` (pass through)

    **Non-JSON / unrecognized event:**
    Input:  `{ raw: 'data: not-valid-json' }`
    Output: frame passed through unchanged (never throw)

    ```typescript
    // packages/server/src/adapters/langchain.ts
    import type { SseFrame, SseTransform } from '../accumulator'
    import type { SseAdapter } from './deepagents'

    function extractLangChainFrame(raw: string): { event: string | null; data: string } {
      // Handle multi-line SSE frames: "event: token\ndata: {...}"
      const lines = raw.split('\n')
      let event: string | null = null
      let data = ''
      for (const line of lines) {
        if (line.startsWith('event: ')) {
          event = line.slice(7).trim()
        } else if (line.startsWith('data: ')) {
          data = line.slice(6)
        }
      }
      return { event, data }
    }

    function langchainToAiSdk(frame: SseFrame, frameIndex: number): SseFrame | null {
      const { event, data } = extractLangChainFrame(frame.raw)

      if (data === '[DONE]') return frame

      // If no event: prefix, treat as passthrough (not LangChain native format)
      if (event === null && !frame.raw.startsWith('data: ')) return frame

      let parsed: Record<string, unknown>
      try {
        parsed = JSON.parse(data) as Record<string, unknown>
      } catch {
        return frame  // Non-JSON — pass through
      }

      // Map by event type (SSE event: header takes precedence; fall back to data.type)
      const eventType = event ?? (parsed.type as string) ?? ''

      switch (eventType) {
        case 'token': {
          const text = (parsed.text as string) ?? ''
          if (!text) return null
          // text-delta: required fields type + delta (AI SDK v6)
          return { raw: `data: ${JSON.stringify({ type: 'text-delta', delta: text })}` }
        }
        case 'message': {
          // LangChain message frame = end of response; emit AI SDK finish
          // DESIGN INTENT: Do NOT re-emit the accumulated content from the message frame.
          // The message frame's `content` field contains the full response text, but this
          // duplicates the token frames already accumulated by AI SDK v6. Emitting it would
          // cause double-counting in the client. Instead, emit ONLY the finish signal.
          // finish: required fields type + finishReason (AI SDK v6)
          return { raw: `data: ${JSON.stringify({ type: 'finish', finishReason: 'stop' })}` }
        }
        case 'tool_call': {
          const toolName = (parsed.tool_name as string) ?? ''
          const toolInput = (parsed.tool_input as Record<string, unknown>) ?? {}
          // Deterministic toolCallId: use tool_call_id from frame if present,
          // otherwise lc-{toolName}-{frameIndex} (frameIndex = tool call count
          // within this request, tracked by the caller). This avoids Date.now()
          // collisions under high throughput and produces reproducible test values.
          const toolCallId = (parsed.tool_call_id as string) ?? `lc-${toolName}-${frameIndex}`
          // tool-input-available: required fields type + toolCallId + toolName + input (AI SDK v6)
          return {
            raw: `data: ${JSON.stringify({
              type: 'tool-input-available',
              toolCallId,
              toolName,
              input: toolInput,
            })}`,
          }
        }
        case 'error':
          return null  // Drop error frames
        default:
          return frame  // Pass through unrecognized event types
      }
    }
    ```

    The `langchainToAiSdk` transform function above takes a `frameIndex` parameter to produce
    deterministic toolCallIds. Because `SseTransform` has signature `(frame: SseFrame) => SseFrame | null`,
    wrap it with a closure that tracks the tool call count:

    ```typescript
    function createLangchainTransform(): SseTransform {
      let toolCallCount = 0
      return (frame: SseFrame): SseFrame | null => {
        const result = langchainToAiSdk(frame, toolCallCount)
        // Only increment counter when a tool_call frame is processed
        if (result !== null && result !== frame) {
          const { event } = extractLangChainFrame(frame.raw)
          const eventType = event ?? ''
          if (eventType === 'tool_call') toolCallCount++
        }
        return result
      }
    }

    export const langchainAdapter: SseAdapter = {
      name: 'langchain',
      transforms: [createLangchainTransform()],
    } as const
    ```
