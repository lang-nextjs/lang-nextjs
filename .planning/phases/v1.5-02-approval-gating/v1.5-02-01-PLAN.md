  <behavior>
    The approval gating feature has three independently testable units:

    1. **approval-registry** — in-memory Map of pending approvals keyed by approvalId.
       Cases:
       - registerApproval(approval) → getApproval(id) returns same object
       - getApproval(id) on non-existent → returns undefined
       - getApproval(id) when expiresAt < Date.now() → marks status "timeout", still returns record
       - resolveApproval(id, "approve") → status becomes "approved"
       - resolveApproval(id, "reject") → status becomes "rejected"
       - resolveApproval on non-existent id → no-op (no throw)
       - cleanupApproval(id) → getApproval(id) returns undefined
       - cleanupExpiredApprovals() → removes entries with expiresAt < now and status !== "approved"; returns count
       - [QUORUM-4] cleanupExpiredApprovals() → ALSO removes entries with status === "approved" AND expiresAt < Date.now() (stale approved entries must be GC'd)
       - Concurrent: two registerApproval calls with different IDs → both retrievable independently

    2. **approvalGating transform** — SseTransform factory returning frame | null.
       Cases:
       - Pass-through when getApprovalConfig returns undefined: tool-input-start frame passes through unchanged
       - Pass-through when getApprovalConfig returns { require: false }: frame passes through unchanged
       - Approval required: createApprovalGatingTransform with require:true → tool-input-start returns data-approval-required frame (NOT the tool-input-start)
       - data-approval-required frame payload: has type="data-approval-required", data with id, seq, actionName (toolName), description, arguments (input), status="waiting", createdAt, expiresAt
       - data-approval-required frame payload: data matches ApprovalSchema from packages/react/src/schemas.ts
       - Buffering (toolCallId-keyed): after approval-required, a subsequent tool-output-available frame for same toolCallId returns null
       - Buffering (toolCallId-keyed): frame for DIFFERENT toolCallId (no pending approval) still passes through
       - [QUORUM-2] Global pause: when any approval is pending (pendingApprovalsByToolCallId.size > 0), a text-delta frame (type: "text-delta") that arrives concurrently is ALSO buffered (returns null, not passed through)
       - [QUORUM-2] Global pause: when all approvals resolve, the previously buffered text-delta frames are drained via readyQueue on subsequent transform calls
       - readyQueue drain: after resolving approval to "approved", next transform call on ANY frame returns the first buffered frame, not the input frame
       - [QUORUM-3] Rejection: transform call when registry entry status="rejected" → returns a `data-error` frame `{ type: "data-error", data: { code: "approval_rejected", message: "Tool execution was rejected" } }` (NOT null)
       - [QUORUM-3] Rejection: after emitting the data-error frame for a rejection, the toolCallId entry is cleared from pendingApprovalsByToolCallId (no further buffering for that toolCallId)
       - [QUORUM-4] Cleanup-after-drain: after approval resolves and readyQueue is fully drained, the transform calls cleanupApproval(approvalId) — verified by getApproval(approvalId) returning undefined after drain completes
       - Pass-through default (no getApprovalConfig): all frames pass through unchanged
       - Non-data frame (no "data: " prefix) passes through unchanged
       - [DONE] frame passes through unchanged

    3. **handler integration** — createDeepAgentsHandler with approvalGating option.
       Cases (added to handler.test.ts):
       - Handler created WITHOUT approvalGating option: tool-input-start frame reaches client (no data-approval-required)
       - Handler created WITH approvalGating: { getApprovalConfig: () => ({ require: true }) }: data-approval-required frame is emitted when tool-input-start arrives
       - Handler with approvalGating enabled: no tool-input-start frame reaches client before approval
       - Handler with approvalGating enabled: approvalGating option with getApprovalConfig returning { require: false } → tool-input-start passes through (per-tool control)
