<objective>
Prove the three v1.6 production flows end-to-end (OPS-05): (1) an observability event reaches a sink, (2) a resilience trip produces the correct fallback (429 rate-limit / 503 breaker-open), and (3) SIGTERM shutdown drains an in-flight stream. Plus a bounded resource-stability test that exercises the abort/timeout path ~50 times as a no-leak proxy — with an explicit documented rationale that a true flaky 1000-abort `lsof` FD check is intentionally NOT shipped in CI.

Per 20-RESEARCH.md and the locked constraints: flows 1 and 2 run at the handler HTTP boundary using the existing in-memory mock-store / mock-fetch patterns (no live backend), and flow 3 is a Node-only Vitest integration test with fake timers and injectable `onExit` (SIGTERM does not fire in a browser, so Playwright is the wrong tool). All four tests live in `packages/server` and reuse the helper patterns already in `handler.resilience.test.ts` and `shutdown.test.ts`.

Purpose: the production-readiness story (hooks, resilience gates, graceful drain built in Phases 18–19) must be proven to work together end-to-end before v1.6.0 ships.
Output: four new test files in `packages/server/src/`.
</objective>
