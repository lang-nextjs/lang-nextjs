  <action>
Create `docs/ERROR-REPORTING.md` documenting how to wire error reporting through the observability `onError` hook. Source of truth for the context shape is `packages/server/src/observability.ts` — the `OnErrorContext` type. Do NOT invent fields; use exactly: `type` ("fetch" | "stream" | "transform" | "rate-limit" | "circuit-breaker"), `error` (Error), `durationMs`, `frameIndex?`, `sessionId`, `timestamp`.

Structure the doc with these sections:
1. **Overview** — error reporting is wired via the vendor-neutral `observability.onError` hook on `createDeepAgentsHandler`; the library bundles NO APM SDK. State explicitly: "Bring your own `@sentry/node` or `@datadog/*` SDK — it is never a dependency of @deepagents-nextjs/*."
2. **The OnErrorContext shape** — a table mapping each field to its meaning and whether it is safe to send to a third party. Mark `sessionId` as potentially user-identifying (scrub if your APM PII policy requires). All other fields are safe scalars (no raw headers/tokens/bodies ever reach the hook — reference OBS-03).
3. **Sentry example** — a TypeScript code block adapted from 20-RESEARCH.md (lines ~327-358): `Sentry.init(...)` once at module scope, then `createDeepAgentsHandler({ backendUrl, observability: { onError: (ctx) => Sentry.captureException(ctx.error, { tags: { error_type: ctx.type }, extra: { sessionId: ctx.sessionId, durationMs: ctx.durationMs, frameIndex: ctx.frameIndex }, level: ctx.type === 'rate-limit' ? 'warning' : 'error' }) } })`. Import the type as `import { createDeepAgentsHandler, type OnErrorContext } from '@deepagents-nextjs/server'`.
4. **Datadog example** — a TypeScript code block adapted from 20-RESEARCH.md (lines ~371-409) calling `datadogRum.addError(ctx.error, { 'error.type': ctx.type, 'session.id': ctx.sessionId })`. Note RUM is browser-side and server traces use the separate Datadog APM package.
5. **Caveats** (from 20-RESEARCH.md Pitfalls 1–3) — (a) onError is READ-ONLY telemetry: throwing or rejecting NEVER aborts the SSE stream and the return value does NOT gate the request (control flow belongs to resilience stores / approval gating); (b) keep the hook fast (< ~10ms) and rely on the APM SDK's internal batching — do not run blocking DB/RPC enrichment inline; (c) `sessionId` may identify a user — scrub before logging if needed.
6. **Required env vars** — note the consumer supplies `SENTRY_DSN` / Datadog `applicationId`+`clientToken`; these are NOT read by this library.

Do NOT add any dependency anywhere. This is documentation only.
