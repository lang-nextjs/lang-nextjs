  <action>
Create packages/server/src/adapters/openSwe.ts. Follow the exact style of langgraph.ts and
langchain.ts.

File structure:
1. JSDoc header documenting: LangGraph astream_events v2 on_tool_start/on_tool_end → AI SDK v6;
   stateless adapter (per-request state via getter); reorder buffer for parallel tool calls;
   FIFO queue for toolCallId pairing (order-independent end-event matching).

2. Type imports:
   import type { SseFrame, SseTransform } from "../accumulator";
   import type { SseAdapter } from "./deepagents";

3. Type:
   type LangGraphEvent = { event: string; name: string; run_id: string; data: Record<string, unknown>; }

4. createOpenSweTransform() factory function — the core stateful unit:
   - Creates per-closure state:
     a. toolCallCounters: Map<string, Map<string, number>>
        Keyed: run_id → (toolName → call count).
        Purpose: generate deterministic toolCallId = `${run_id}--${toolName}-${count}` on start.
     b. pendingToolCallIds: Map<string, string[]>
        Keyed: `${run_id}--${toolName}` → ordered list of generated toolCallIds not yet matched
        to an end event. On on_tool_start, push the new toolCallId; on on_tool_end, shift() to
        retrieve the correct toolCallId. This FIFO queue is correct because for a given
        (run_id, toolName) pair, start events and their corresponding end events correspond in
        FIFO order even if other tools' end events interleave.
        IMPORTANT: do NOT use a separate "completed counter" to reconstruct toolCallId on end.
        The queue shift() is the only correct mechanism.
     c. startOrder: string[]
        Ordered list of toolCallIds as they were started (head = oldest unfinished).
        Used by the reorder buffer to enforce emission order.
     d. endBuffer: Map<string, SseFrame>
        Buffered end-event output frames, keyed by toolCallId, not yet emitted.

   - Returns a SseTransform function that handles:

     Passthrough rules (apply first):
     - If !line.startsWith("data: ") → return frame
     - If raw === "[DONE]" → return frame
     - If JSON parse fails → return frame
     - If !parsed.event → return frame

     Switch on parsed.event:

     case "on_chat_model_stream":
       Identical to langGraphAdapter: extract chunk.content, return text-delta if non-empty
       string, else null. (This makes openSweAdapter a superset of langGraphAdapter.)

     case "on_tool_start":
       - Extract: toolName = parsed.name, run_id = parsed.run_id,
         input = (parsed.data?.input as Record<string, unknown>) ?? {}
       - Get/init counter for (run_id, toolName); compute toolCallId = `${run_id}--${toolName}-${count}`
       - Increment counter
       - Push toolCallId onto the FIFO queue:
           const queueKey = `${run_id}--${toolName}`
           const queue = pendingToolCallIds.get(queueKey) ?? []
           queue.push(toolCallId)
           pendingToolCallIds.set(queueKey, queue)
       - Push toolCallId to startOrder queue
       - Return frame: data: JSON.stringify({ type: "tool-input-start", toolCallId, toolName, input })

     case "on_tool_end":
       - Extract: toolName = parsed.name, run_id = parsed.run_id,
         output = parsed.data?.output ?? null
       - Retrieve toolCallId from the FIFO queue (shift — NOT counter reconstruction):
           const queueKey = `${run_id}--${toolName}`
           const toolCallId = pendingToolCallIds.get(queueKey)?.shift()
           if (toolCallId === undefined) return null  // no matching start — drop
       - Build output frame: data: JSON.stringify({ type: "tool-output-available", toolCallId, output })
       - Reorder logic:
         if (startOrder[0] === toolCallId):
           // This end event matches the head of the start queue — emit it and drain buffer
           startOrder.shift()
           const framesToEmit = [outputFrame]
           // Drain any buffered ends that are now unblocked (next in start order)
           while (startOrder.length > 0 && endBuffer.has(startOrder[0])) {
             const nextId = startOrder.shift()!
             framesToEmit.push(endBuffer.get(nextId)!)
             endBuffer.delete(nextId)
           }
           // Return the first frame; attach extras via a side-channel approach:
           // Since SseTransform returns SseFrame | null (one frame), combine multiple frames
           // into a single frame by joining with \n\n.
           // The handler splits on \n\n before writing, so this is safe.
           if (framesToEmit.length === 1) return framesToEmit[0]!
           // Multiple frames: join raw content with \n\n so the SSE writer emits them as
           // separate frames. The handler processes each \n\n-separated chunk as a frame.
           return { raw: framesToEmit.map(f => f.raw).join('\n\n') }
         else:
           // Out-of-order end event — buffer it
           endBuffer.set(toolCallId, outputFrame)
           return null

     default:
       return null

5. Export:

   export const openSweAdapter: SseAdapter = {
     name: "open-swe",
     get transforms(): SseTransform[] {
       return [createOpenSweTransform()];
     },
   } as const;
