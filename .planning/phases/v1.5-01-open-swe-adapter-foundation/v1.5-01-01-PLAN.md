    on_tool_start event:
      Input:  data: {"event":"on_tool_start","name":"bash_execute","run_id":"run-abc","data":{"input":{"command":"git status"}}}
      Output: data: {"type":"tool-input-start","toolCallId":"run-abc--bash_execute-0","toolName":"bash_execute","input":{"command":"git status"}}
      Rule: toolCallId = `${run_id}--${toolName}-${counter}` where counter starts at 0 per (run_id, toolName) pair.

    on_tool_end event:
      Input:  data: {"event":"on_tool_end","name":"bash_execute","run_id":"run-abc","data":{"output":"On branch main"}}
      Output: data: {"type":"tool-output-available","toolCallId":"run-abc--bash_execute-0","output":"On branch main"}
      Rule: toolCallId is retrieved by shifting from the FIFO queue for (run_id, toolName) —
      NOT reconstructed via a counter. Each on_tool_start pushes its generated toolCallId onto
      the queue; each on_tool_end shifts the oldest entry off.

    tool_call_id linking (pairing):
      A start event and its matching end event must produce identical toolCallId values.
      Verify: parse both outputs and assert toolCallId values are equal.

    Reorder buffer (ADAPT-04):
      Scenario: two on_tool_start events arrive (tool A, tool B). Then on_tool_end for tool B
      arrives BEFORE on_tool_end for tool A. The adapter must buffer the tool B end event and
      emit tool A end first (once tool A end arrives), so output order matches start order.
      Test: simulate reversed on_tool_end arrival; assert emitted frames are in tool_call_id
      order matching the start sequence.
      Implementation note: the reorder buffer is per-request state in the transform closure.
      The createOpenSweTransform() factory returns a stateful SseTransform.

    Same-tool FIFO queue test (ADAPT-04 — order-independent toolCallId lookup):
      Scenario: two on_tool_start events for the SAME toolName ("bash_execute") within the
      same run arrive sequentially → toolCallId_0 and toolCallId_1. Then on_tool_end for the
      SECOND call (toolCallId_1) arrives BEFORE the first (toolCallId_0).
      Expected: each end event is paired with its correct toolCallId from the queue, not a
      reconstructed counter. The end that arrives second (for call 0) should carry toolCallId_0;
      the end that arrives first (for call 1) should carry toolCallId_1 — but toolCallId_1 end
      is buffered until toolCallId_0 end is received (reorder buffer keeps emission in start order).
      Test: assert toolCallId on the first emitted end frame equals toolCallId_0, and the
      second emitted end frame equals toolCallId_1.

      - Non-data: lines pass through unchanged
      - JSON without event field passes through unchanged

   when an end event arrives, if it matches the head of the queue, emit it and also emit
   any subsequent buffered ends. If it does NOT match the head, buffer it.
