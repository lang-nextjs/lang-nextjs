<objective>
Ship the stateless resilience gate: consumer-provided `RateLimitStore` and `CircuitBreakerStore` interfaces plus a `ResilienceConfig`, with handler integration that rejects over-limit requests with 429 and OPEN-breaker requests with 503 BEFORE any backend fetch, records outcomes into the breaker after the stream, holds zero module-scope state, and exposes the existing retry policy via handler options (mid-stream failures never retried). Rejections fire the Plan-01 `onError` hook.

Depends on Plan 01 because rate-limit/circuit-breaker rejections fire `observability.onError` (shared interface).

Purpose: Consumers can protect their backend under load (rate limit, breaker) using any store backend (Redis, DynamoDB, in-memory) with correct behavior under serverless/edge invocation isolation.
Output: resilience.ts interfaces + checks, handler integration, exports, unit + integration tests.
</objective>
