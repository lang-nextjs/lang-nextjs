<objective>
Ship stateless liveness/readiness probe factories that follow Kubernetes conventions: a cheap liveness probe, a readiness probe that flips to not-ready when draining or a declared dependency is down, optional fast consumer-supplied checks, minimal info-leaking-free responses — and copy them into sveltekit/remix/edge so they are framework-agnostic and Next.js-free in edge.

This plan is independent of observability (Plan 01) and runs in parallel in Wave 1.

Purpose: Consumers can health-check the handler in production (K8s liveness/readiness, canary gates) without exposing internal info or making expensive backend round-trips on the readiness path.
Output: health.ts + tests in server, exports, and copied health.ts in three framework packages.
</objective>

Then write `packages/server/src/health.ts`:
  - `createHealthProbe(checks?: Array<{ name: string; check: () => Promise<boolean>; timeoutMs?: number }>)` → `Promise<{ ok: boolean; status: "ok" | "error"; checks: Record<string, boolean>; timestamp: number }>`. Base on RESEARCH Pattern 2 (lines 261–295) but ADD a `status` string and DROP any field that could leak internals.

Dependency checks are OPTIONAL and consumer-supplied (same shape as liveness checks). If draining → ready:false, status:"draining". If any check fails → ready:false, status:"error".
