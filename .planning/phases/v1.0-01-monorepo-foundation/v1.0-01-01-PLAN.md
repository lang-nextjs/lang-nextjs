```json
  "name": "deepagents-nextjs-monorepo",
  "version": "0.0.0",

  "scripts": {
    "build": "turbo build",
    "test": "turbo test",
    "typecheck": "turbo typecheck",
    "lint": "turbo lint"
  },
  "devDependencies": {
    "turbo": "^2.9.6",
    "typescript": "^5.8.3"
  }
}
```

**pnpm-workspace.yaml** — workspace glob discovery:
```yaml
packages:
  - 'packages/*'
  - 'apps/*'
```

**turbo.json** — Turborepo v2 schema. MUST use `"tasks"` key (not `"pipeline"` — deprecated in v2):
```json
{
  "$schema": "https://turborepo.dev/schema.json",
  "tasks": {
    "build": {
      "dependsOn": ["^build"],
      "outputs": ["dist/**"]
    },
    "test": {
      "dependsOn": ["build"],
      "outputs": ["coverage/**"]
    },
    "typecheck": {
      "dependsOn": ["^build"],
      "outputs": []
    },
    "lint": {
      "dependsOn": [],
      "outputs": []
    }
  }
}
```

`"^build"` in `dependsOn` means: build all upstream workspace packages first. This enforces server → react → example ordering without any manual configuration.

**.gitignore** — covers build artifacts and tooling caches so they never appear as untracked files after a build:
```

# Dependencies
node_modules/

# Turborepo cache
.turbo/

# Test coverage
coverage/
```

Create two files.

**tsconfig.base.json** at repo root — shared strict config extended by all packages. Uses `"moduleResolution": "bundler"` (not `"node16"` or `"nodenext"` — those require explicit `.js` extensions on every relative import, incompatible with tsup's default behavior):
```json
{
  "compilerOptions": {
    "target": "ES2020",
    "lib": ["ES2020"],
    "module": "ESNext",
    "moduleResolution": "bundler",
    "declaration": true,
    "declarationMap": true,
    "strict": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "isolatedModules": true,
    "resolveJsonModule": true
  }
}
```

**apps/example/package.json** — private placeholder so Turborepo includes the `apps/example` workspace in its graph. Declares workspace dependencies on both packages so Turborepo's `dependsOn: ["^build"]` enforces the correct build ordering (server → react → example). No Next.js dependency yet (that ships in Phase v1.0-04):
```json
{
  "name": "example",
  "version": "0.0.0",
  "private": true,
  "scripts": {
    "build": "echo 'example placeholder — no build yet'",
    "dev": "echo 'example placeholder — no dev yet'",
    "test": "echo 'no tests in example'"
  },
  "dependencies": {
    "@deepagents-nextjs/server": "workspace:*",
    "@deepagents-nextjs/react": "workspace:*"
  }
}
```

The `build` script must exist as a no-op so `turbo build` does not error when it reaches this workspace. The `test` script must exist as a no-op so `turbo test` does not fail/warn when run across all workspaces. The `workspace:*` dependencies on both packages ensure Turborepo traverses the dependency graph correctly and builds server before react before example.
