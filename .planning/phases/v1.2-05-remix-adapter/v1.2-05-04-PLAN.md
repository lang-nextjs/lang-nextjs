  <action>
Read the existing .github/workflows/ci.yml to understand the current CI structure.

The existing sveltekit guard checks:
```yaml
- name: Check - @deepagents-nextjs/sveltekit has no React/Next.js in dist
  run: |
    grep -rE 'require\("(react|next)' packages/sveltekit/dist/index.js packages/sveltekit/dist/index.mjs \
      && echo "FAIL: React/Next.js leaked into sveltekit dist" && exit 1 \
      || echo "Clean: no React/Next.js in sveltekit dist"
```

Add a NEW step AFTER the sveltekit guard for the remix package. The remix guard must:
1. Check ONLY for `@deepagents-nextjs/react` and `@deepagents-nextjs/server` — NOT for `react` alone (the hook legitimately requires react)
2. Check BOTH dist/index.js and dist/index.mjs
3. Exit 1 on match (fail), echo clean on no-match (pass)
4. Use patterns that match both CJS `require(` syntax and ESM `from "` syntax to catch both output formats

Add this step to ci.yml after the sveltekit guard:
```yaml
      - name: Check - @deepagents-nextjs/remix handler has no @deepagents-nextjs/* cross-package imports in dist
        run: |
          grep -rE 'require\("@deepagents-nextjs/(react|server)|from "@deepagents-nextjs/(react|server)' \
            packages/remix/dist/index.js packages/remix/dist/index.mjs \
            && echo "FAIL: @deepagents-nextjs cross-package imports leaked into remix dist" && exit 1 \
            || echo "Clean: no @deepagents-nextjs cross-package imports in remix dist"
```

WHY these exact patterns:
- `require\("@deepagents-nextjs/(react|server)` — catches CJS bundled import of @deepagents-nextjs/react or @deepagents-nextjs/server in dist/index.js
- `from "@deepagents-nextjs/(react|server)` — catches ESM bundled import in dist/index.mjs
- Does NOT check `react` alone — the hook legitimately uses useState/useEffect from react; tsup externals prevent react from being bundled in, but the import reference may still appear in ESM output as `from "react"`
- The attw check from Plan 01 already catches bundled react (via the duplicate React instance detection)

WHY this guard is scoped to @deepagents-nextjs/* only (not react):
- tsup.config.ts has `external: ['@remix-run/node', '@remix-run/react', 'react']` which prevents react from being bundled
- The actual risk is accidentally importing from @deepagents-nextjs/react or @deepagents-nextjs/server (which would pull in next.js as a peerDep)

Also update the remix package to include a build step that CI can rely on. Verify the Turborepo pipeline already covers remix via the packages/* glob (STATE.md v1.2-04 decision: "Turborepo covers sveltekit via packages/* glob — no per-package CI changes needed"). The CI runs `pnpm build` and `pnpm test` at the monorepo level, which Turborepo routes to each package including remix.
