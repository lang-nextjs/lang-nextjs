**E2E-01: Auth cookie forwarded as Authorization: Bearer**

The existing route.ts uses `createDeepAgentsHandler` without `getToken`. To test auth E2E, the test MUST intercept at the route level and verify that the route injects the Authorization header. The approach is:

1. In the test, navigate to the Next.js app (`page.goto('/')`).
2. Set a cookie via `page.context().addCookies([{ name: 'session', value: 'test-token-abc', url: 'http://localhost:3000' }])`.
3. Install a `page.route('**/api/chat/stream', async (route) => { ... })` intercept.
4. In the intercept, capture `route.request().headers()` to check for the `authorization` header.
5. The route.ts already reconstructs the request but does NOT have getToken configured — so the Authorization header will NOT be injected by the server handler (no getToken). Instead, this test verifies the CLIENT-side getToken path via the hook.
6. For client-side auth test: modify the test page approach — create a dedicated test route at `apps/example/app/api/chat/stream/test-auth/route.ts` that wraps `createDeepAgentsHandler({ backendUrl: '...', getToken: getCookieToken('session') })`. Then intercept calls to `/api/chat/stream/test-auth` and check the `authorization` header the handler would inject.

ACTUALLY: The simplest approach that avoids creating a new route is:
- The hook's `getToken` option allows client-side token injection. The test can load a page where `useDeepAgentsChat` is called with `getToken: () => document.cookie` style. But this is fragile.

CORRECT APPROACH for E2E-01:
- Create a dedicated test-only API route `apps/example/app/api/chat/stream/test-auth/route.ts` that uses `getCookieToken('session')` and proxies to a fake backend URL.
- In the E2E test, intercept requests to `**/api/chat/stream/test-auth` to:
  1. Read the `authorization` header from the intercepted backend-bound request — BUT page.route intercepts the browser→Next.js leg, not the Next.js→backend leg.
- Since page.route only intercepts browser→server traffic, the correct approach is:
  - Intercept `/api/chat/stream/test-auth` — the route handler will call getCookieToken, extract the cookie, and forward `Authorization: Bearer test-token-abc` to BACKEND_URL.
  - BUT we can't inspect the Next.js→backend header from Playwright.
  
SIMPLEST CORRECT APPROACH:
- Create `apps/example/app/api/chat/stream/test-auth/route.ts` that: (a) reads the cookie using getCookieToken, (b) returns the extracted token in a JSON response so the test can verify it.
- This is a test-only echo handler, not a real proxy.

Implementation steps:

**Create `apps/example/app/api/chat/stream/test-auth/route.ts`:**
```typescript
import { getCookieToken } from '@deepagents-nextjs/server';
import { NextRequest } from 'next/server';

export const dynamic = 'force-dynamic';

// TEST-ONLY: echoes the Authorization token getCookieToken would inject.
// Not a real proxy — used by E2E tests to verify cookie → Bearer token flow.
export async function POST(request: NextRequest): Promise<Response> {
  const getToken = getCookieToken('session');
  const token = await getToken(request);
  return Response.json({ authorization: token ? `Bearer ${token}` : null });
}
```
