## Implementation Decisions

### Per-Instance EventSource (Stream Isolation)

**Decision:** No module-level EventSource map; each `useRunStream` hook instance owns its EventSource ref.

**Rationale:** 
- Simplifies cleanup (return () => ref.close() in useEffect)
- Eliminates global state management
- Naturally isolates streams per-component-instance
- Test confirms two simultaneous hooks with different runIds don't share events

**Verification:** 
- Grep shows no `global.` references in useRunStream.ts
- EventSourceRef scoped to component instance (line 25)
- Cleanup handler runs on unmount (line 73)

### Two-Pass Tool State Accumulation

**Decision:** `useToolState` processes tool-input-start and tool-output-available in separate passes with a `pendingOutputs` Map.

**Rationale:**
- Handles out-of-order events: output may arrive before input (edge case in streamed systems)
- Map keyed by `toolCallId` (not toolName) prevents cross-run leakage
- Duplicate tool-output-available events are idempotent (first output wins)

**Verification:**
- Test "out-of-order convergence" passes with output arriving before input
- Both orderings result in completed state
- useToolState.test.ts lines 505-517 verify correctness

### Suspense Wrapper + useSearchParams

**Decision:** RunDetailPage wraps RunDetailContent in Suspense; RunDetailContent uses `useSearchParams()` from next/navigation.

**Rationale:**
- `useSearchParams()` is a dynamic hook requiring Suspense boundary in Next.js App Router
- Avoids SSR hydration mismatch (window.location.search not available on server)
- Per Next.js App Router pattern

**Verification:**
- Suspense wrapper present (line 64)
- useSearchParams import from next/navigation (line 4)
- Test mocks useSearchParams correctly

### Full JSON Payloads (No Truncation)

**Decision:** ToolCard uses `JSON.stringify(tool.input, null, 2)` and `JSON.stringify(tool.output, null, 2)`.

**Rationale:**
- Requirement DASH-04 specifies "full input payload and output result"
- 2-space indent improves readability
- No custom summarization or field filtering

**Verification:**
- Lines 32 and 36 of ToolCard.tsx show full stringify
- Test "shows input and output payload when expanded" confirms full JSON visible

### Missing threadId Guard

**Decision:** Page returns early error state when threadId is absent or empty.

**Rationale:**
- Silent empty-string fallback creates invisible bugs
- Requirement DASH-05 implies explicit error state when precondition missing
- Guides user to correct URL format

**Verification:**
- Lines 14-22 of page.tsx show early return
- Test "shows error state when threadId is missing" passes
- Error message visible in test: "threadId is required"
