<objective>
Configure Vercel deployment strategy (canary) and rollback triggers for the open-swe Next.js app so new versions can be rolled out gradually and reverted automatically on error spikes.
</objective>

<context>
@.planning/phases/17-00-canary-blue-green/17-00-RESEARCH.md

This plan depends on plan 17-01 (health endpoint exists) because the rollback health check will probe `/health`. It creates `apps/open-swe/vercel.json` with canary configuration and documents rollback CLI usage.

Note: Vercel Pro+ is required for built-in automatic rollback on 5xx. The plan documents both the dashboard configuration (for Pro+) and the GitHub Actions-based rollback using `vercel rollback` CLI (works on any tier).
</context>

<tasks>

<task type="auto">
  <name>Create vercel.json with canary traffic split and rollback config</name>
  <files>apps/open-swe/vercel.json</files>
  <action>
    Create `apps/open-swe/vercel.json` with the following configuration:

    ```json
    {
      "framework": "nextjs",
      "buildCommand": "pnpm turbo build --filter=open-swe",
      "devCommand": "pnpm turbo dev --filter=open-swe",
      "installCommand": "pnpm install",
      "regions": ["iad1"],
      "traffic": {
        "split": [
          { "path": "/health", "vitality": 100 },
          { "path": "/*", "vitality": 100 }
        ]
      },
      "rollback": {
        "automatic": true,
        "errorThreshold": 10
      }
    }
    ```

    Key configuration:
    - `framework: nextjs` — identifies as Next.js project to Vercel
    - `buildCommand` uses turbo filter to build only open-swe
    - `regions: ["iad1"]` — single region for now (Virginia, closest to backends)
    - `traffic.split` — routes all traffic to the current deployment (100% vitality); canary deployments would use a split like 90/10
    - `rollback.automatic: true` — enables Vercel built-in auto-rollback (Pro+ feature)
    - `rollback.errorThreshold: 10` — rollback when error rate exceeds 10%

    For canary deployments, the workflow uses `vercel deploy --canary --environment=preview` for pre-production testing. The `vercel promote` command shifts traffic gradually.

    Rollback is triggered via:
    ```bash
    vercel rollback [deployment-url] --token=$VERCEL_TOKEN
    ```
    This works on any Vercel plan (no Pro required for CLI rollback).
  </action>
