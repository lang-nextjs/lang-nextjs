# Phase v1.0-03: React Package — Research

**Phase:** v1.0-03 — React Package
**Goal:** A React component can call `useDeepAgentsChat()` and receive fully typed messages including DeepAgents-specific `data-*` parts, with no duplicate React or Zod instances
**Researched:** 2026-04-29

---

## Summary

Phase v1.0-03 ports a focused subset of the stsfront `lib/chat` and `hooks/use-chat-companion.ts` into `@deepagents-nextjs/react`. The deliverables are: (1) four Zod schemas exported as `PlanSchema`, `TaskSchema`, `FileSchema`, `ApprovalSchema`; (2) a typed discriminated union `Message = UserMessage | AIMessage | ToolCallMessage | ErrorMessage`; (3) a `partsToMessages()` converter that walks AI SDK `UIMessage.parts[]` and produces `Message[]`; and (4) a `useDeepAgentsChat({ sessionId, endpoint, getToken? })` hook that wires `DefaultChatTransport` and calls `partsToMessages()` internally.

Everything app-specific in use-chat-companion.ts is stripped: boardId, chatMode, agentType, localStorage session cache, SWR history merge, optimistic approval overlay, tool-call board invalidation, cancel/approve/reject mutations.

## User Constraints (from CONTEXT.md)

- Hook API: `useDeepAgentsChat({ sessionId, endpoint, getToken? })` — returns `{ messages, sendMessage, status, error }`
- Message union: discriminated on `type` field — `'user' | 'ai' | 'tool-call' | 'error'` only (four variants)
- Schema exports: `PlanSchema`, `TaskSchema`, `FileSchema`, `ApprovalSchema` (short names, not `DataPlan*`)
- peerDependencies: add `ai: ^4.0.0`, `@ai-sdk/react: ^1.0.0`, `zod: ^3.0.0 || ^4.0.0`
- No bundled React, AI SDK, or Zod — peerDeps only
- `partsToMessages(aiMessages, isStreaming)`: drops all data-* except data-error (log+skip)
- `'use client'` directive at top of hook file
- `getToken?: () => Promise<string | null> | string | null` — same fail-open semantics as server package

Note: `ai` package version in stsfront is `^6.0.154` but the package name is `ai` with AI SDK v6. The peerDep range `>=4.0.0` accepts AI SDK v4+. The `@ai-sdk/react` is `^3.0.156` in stsfront (AI SDK v6 splits react into `@ai-sdk/react@3.x`).

### Zod v3/v4 Compatibility

The schemas use `z.object()`, `z.string()`, `z.number()`, `z.boolean()`, `z.enum()`, `z.array()`, `.nullish()`, `.optional()` — all stable across Zod v3 and v4. No `z.discriminatedUnion()` in the exported schemas (that was in the app-specific `AiSdkDataPartSchema`). Safe to declare `zod: >=3.0.0` as peerDep.

### parseDataPart() scoped to 4 schemas

The stsfront `parseDataPart()` uses `AiSdkDataPartSchema` (a full discriminated union with 9 variants). The package version is scoped: tries each of the 4 schemas + DataErrorSchema by type field. Returns `{ ok: true, type, data }` or `{ ok: false }`. Does not use a discriminated union — uses simple `switch` on type string then individual `safeParse`.

### partsToMessages() converter

Stripped version of `partsToMessages` in stsfront:
- Walk each `UIMessage` in `aiMessages`
- For user role: emit `UserMessage`
- For assistant role: single pass over `parts[]`, accumulate text buffer, flush on tool-call
  - `type === 'text'` → add to buffer
  - `type === 'dynamic-tool'` or `type.startsWith('tool-')` → flush, emit `ToolCallMessage`
  - `type === 'data-error'` → parse via `DataErrorSchema.safeParse()`, emit `ErrorMessage`
  - All other `data-*` types → `console.warn` + skip
  - After parts loop: flush trailing text
  - Apply `isStreaming` flag to last `AIMessage` bubble
- Returns flat `Message[]`

No SeqBuffer, no upsert, no plan/task/file/approval buckets. Simpler than stsfront.

### useDeepAgentsChat() hook

```typescript
'use client'
import { useChat } from '@ai-sdk/react'
import { DefaultChatTransport } from 'ai'
import { useMemo } from 'react'
import type { UseDeepAgentsChatOptions, UseDeepAgentsChatReturn } from './types'
import { partsToMessages } from './converter'

export function useDeepAgentsChat({ sessionId, endpoint, getToken }: UseDeepAgentsChatOptions): UseDeepAgentsChatReturn {
  const transport = useMemo(() => new DefaultChatTransport({
    api: endpoint,
    headers: async () => {
      if (!getToken) return {}
      const token = await Promise.resolve(getToken())
      return token ? { Authorization: `Bearer ${token}` } : {}
    },
    body: () => ({ sessionId }),
  }), [endpoint, sessionId]) // getToken excluded: stable ref assumed

  const { messages: aiMessages, sendMessage: aiSendMessage, status, error } = useChat({ transport })
  const isStreaming = status === 'streaming' || status === 'submitted'
  const messages = useMemo(() => partsToMessages(aiMessages, isStreaming), [aiMessages, isStreaming])

  return {
    messages,
    sendMessage: (text: string) => aiSendMessage({ text }),
    status: isStreaming ? (status as 'streaming' | 'submitted') : error ? 'error' : 'idle',
    error: error ?? null,
  }
}
```

### Test Strategy

**Types and schemas** — pure unit tests, no React, no jsdom needed (run in node environment). However vitest.config.ts already sets `environment: 'jsdom'` globally — this is fine for pure TS tests too.

**Converter** — pure function tests: call `partsToMessages([...uiMessages], isStreaming)` and assert on returned `Message[]`. Mock `UIMessage` objects directly (plain objects). No React needed.

**Hook** — renderHook tests via `@testing-library/react`. Mock `useChat` from `@ai-sdk/react` via `vi.mock('@ai-sdk/react', ...)`. Assert that `messages` is derived from `partsToMessages()` output. Need `@testing-library/react` in devDeps.

The tsup config already sets `external: ['react', 'react-dom', 'ai', '@ai-sdk/react', 'zod']` — this ensures none of the peer deps are bundled. The `exports` field in package.json follows the same dual ESM/CJS pattern as the server package. No additional changes needed.

## Pitfalls

1. **`'use client'` directive must be the first line of hook.ts** — TSup bundles it; if it appears after imports, Next.js App Router will fail at runtime. Write it as a string literal comment before any imports.

2. **Zod import compatibility** — Do not use `import { z } from 'zod/v4'` (Zod v4 compat path). Use `import { z } from 'zod'` which resolves correctly in both v3 and v4.

3. **getToken memoization** — `getToken` is excluded from the `useMemo` dep array for `transport` (matching stsfront pattern for stable callbacks). Document this in a comment.

4. **UIMessage from 'ai'** — The type is `UIMessage` from the `ai` package (not from `@ai-sdk/react`). The `useChat` hook from `@ai-sdk/react` returns `messages: UIMessage[]`. In tsconfig, `skipLibCheck: true` handles cross-package type compatibility.

5. **DOM lib in tsconfig** — `crypto.randomUUID()` requires `DOM` lib. The react tsconfig already has `"jsx": "react-jsx"` but the lib array from base is `["ES2020"]` only. Must add `"DOM", "DOM.Iterable"` to packages/react/tsconfig.json (same fix as server package).

6. **@testing-library/react not in skeleton devDeps** — Add it. Also add `@testing-library/jest-dom` if needed for `.toBeInTheDocument()` matchers (not required for hook-only tests).

7. **No `PlanSubtaskSchema` in the 4-schema list from ROADMAP** — ROADMAP mentions `PlanSchema`, `TaskSchema`, `FileSchema`, `ApprovalSchema`. Export `PlanSubtaskSchema` too (it's a sub-schema required by `PlanSchema`). Export `DataErrorSchema` as well (used internally by converter). Both are useful for callers.
