## Summary

Phase v1.3-01 is the critical-path delivery of v1.3: runnable examples for every shipped framework package and complete API reference documentation. It has zero external dependencies (all packages shipped in v1.2) and zero infrastructure changes (Turborepo globs auto-pick new apps).

The work splits into three groups: (1) new example apps (`apps/sveltekit-example`, `apps/remix-example`), (2) extensions to `apps/example` (adapter swap UI, auth demo, generic types, debug toggle, consumer test file), and (3) six README files plus a root `docs/TESTING.md`. No new packages ship in this phase.

The highest-risk work is the SvelteKit and Remix example apps — two pitfalls (Vite HMR port conflicts at ports 24679/24680, pnpm hoisting resolution) are well-documented and have known prevention patterns. Both must be added to CI `build` + `typecheck` on every PR to prevent example rot. The documentation work is low-risk but high-volume: six READMEs each follow the same template (one-liner install, two-line quick start, API reference, troubleshooting).

**Primary recommendation:** Parallelize documentation tasks (one per package) with example app tasks. Block CI merge on example build + typecheck passing. Use `chunkDelayMs: 0` in all test examples for fast vitest suites.

  beforeEach(() => {
    vi.restoreAllMocks();
  });

  it('accumulates messages from SSE stream', async () => {
    const mockResponse = await createMockDeepAgentsServer({ chunkDelayMs: 0 });
    vi.spyOn(globalThis, 'fetch').mockResolvedValueOnce(mockResponse);

    const { result } = renderHook(() =>
      useDeepAgentsChat({ sessionId: 'test-1', endpoint: '/api/chat/stream' })
    );

    await act(async () => {
      result.current.sendMessage('hello');
      // Wait for stream to complete
      await new Promise((r) => setTimeout(r, 100));
    });

    expect(result.current.messages.length).toBeGreaterThan(0);
    expect(result.current.status).toBe('idle');

### Anti-Patterns to Avoid

- **No Tailwind/shadcn in examples:** Ship bare HTML/CSS. Framework-agnostic UI avoids introducing opinionated styling that distracts from the library pattern.
- **No useFetcher in Remix example:** `useFetcher` buffers full response — cannot stream SSE. Hook must use native `fetch()` + `ReadableStream` loop (already implemented in `packages/remix/src/hook.ts`).
- **No `import from 'next/server'` in SvelteKit/Remix examples:** Cross-framework leakage. Each example imports ONLY from its own framework package (`@deepagents-nextjs/sveltekit` or `@deepagents-nextjs/remix`).
- **No global vitest config for example test:** `apps/example/vitest.config.ts` must be per-package (no root workspace config — deprecated in Vitest 3.2+, per v1.0-01 decision).
- **No chunkDelayMs defaults in tests:** Always pass `chunkDelayMs: 0` in test suites. Default 50ms makes tests slow.

## Common Pitfalls

### Pitfall 1: Vite HMR Port Conflict (EADDRINUSE)
**What goes wrong:** Running `turbo dev` from the monorepo root starts both `apps/sveltekit-example` and `apps/remix-example`. Both default to HMR port 24678. Second app fails with `EADDRINUSE`.
**Why it happens:** Vite defaults all instances to port 24678. No automatic assignment in monorepo context.
**How to avoid:** Override HMR port in each app's `vite.config.ts`: sveltekit-example → 24679, remix-example → 24680.
**Warning signs:** One app's HMR works, the other does not. File changes don't hot-reload in second app.

### Pitfall 2: pnpm Hoisting + Vite Resolution Mismatch
**What goes wrong:** Vite dev server starts from `apps/sveltekit-example/` or `apps/remix-example/`. Cannot find hoisted dependencies (e.g., `zod`, `ai`, `react`) that pnpm placed in root `node_modules/.pnpm`.
**Why it happens:** pnpm uses a non-flat hoisting structure. Vite running from a subdirectory may not traverse up correctly.
**How to avoid:** Add `resolve.dedupe` in `vite.config.ts` for shared singleton packages (`react`, `react-dom`, `ai`, `svelte`). Test both `dev` and `build` commands.
**Warning signs:** Works in CI (`turbo build` from root) but fails locally (`pnpm dev` from app directory).

### Pitfall 3: Example App Not in CI Build
**What goes wrong:** Example apps pass typecheck on creation day but break silently as framework versions advance. Consumers clone examples 3 months later and hit module resolution errors.
**Why it happens:** Example apps not wired into CI — only packages are tested.
**How to avoid:** CI `pnpm build` and `pnpm typecheck` via Turborepo auto-picks `apps/*` via glob. No explicit CI change needed — Turborepo already runs `build` and `typecheck` across all workspaces. Verify CI logs include `sveltekit-example` and `remix-example` build steps after adding the apps.
**Warning signs:** CI passes but example apps are not listed in Turborepo build output.

### Pitfall 4: README Examples That Don't Compile
**What goes wrong:** README code blocks contain outdated API calls (e.g., `useDeepAgentsChat` with old options shape). Consumers copy-paste and get type errors.
**Why it happens:** READMEs are hand-authored; no compile-time validation.
**How to avoid:** All README code examples must match exact exported API signatures confirmed from `src/index.ts` files. For each README, verify the quick-start example matches the shipped exports before committing.
**Warning signs:** README shows `sendMessage(text)` but hook exports `start()` (the Remix hook has `start()`, the React hook has `sendMessage()`).

### Pitfall 5: getCookieToken Demo Using Wrong API
**What goes wrong:** EX-04 demo uses `cookies()` from `next/headers` instead of `getCookieToken()`. Works in Server Components but throws in Route Handlers.
**Why it happens:** Two cookie APIs in Next.js App Router with overlapping names; `next/headers` is server-components-only.
**How to avoid:** Use `getCookieToken(cookieName)` from `@deepagents-nextjs/server`. It calls `NextRequest.cookies.get()` (synchronous Web API), which works in Route Handlers. Do NOT import `cookies` from `next/headers`.
**Warning signs:** `Error: cookies() was called outside a request scope` at runtime.

### Pitfall 6: DEBUG Toggle Using Wrong Env Var Check
**What goes wrong:** EX-04 debug logging demo toggles `process.env.DEBUG` in the browser (`"use client"` component). `process.env` is server-side only in Next.js; client components receive `undefined`.
**Why it happens:** `DEBUG=deepagents:sse` is a server-side environment variable. `shouldDebug()` reads `process.env.DEBUG` which is a Node.js server concept.
**How to avoid:** The debug demo belongs in the **route handler** (server-side), not the client component. Show `DEBUG=deepagents:sse node ...` usage in the README, not as a UI toggle. If a UI toggle is needed, use `NEXT_PUBLIC_SHOW_DEBUG_INFO` which Next.js inlines into client bundles.

### Pitfall 7: SvelteKit Handler vs. Store API Confusion
**What goes wrong:** SvelteKit example uses `createDeepAgentsStore` as a server-side handler, or uses `createDeepAgentsHandler` in a client component. APIs are framework-layer-specific.
**Why it happens:** Both APIs are in `@deepagents-nextjs/sveltekit`; their distinct roles are not obvious from the package name.
**How to avoid:** `createDeepAgentsHandler` goes in `+server.ts` (server-side route). `createDeepAgentsStore` goes in `+page.svelte` (client component). The example must clearly separate these two files.

2. **SvelteKit `createDeepAgentsStore` vs. `useDeepAgentsChat` in example?**
   - What we know: `@deepagents-nextjs/sveltekit` exports `createDeepAgentsStore` (Svelte-native). `@deepagents-nextjs/react` exports `useDeepAgentsChat` (React hook).
   - What's unclear: The EX-02 requirement says "uses `createDeepAgentsHandler(RequestEvent)` + `createDeepAgentsStore()`" — confirming Svelte store (not React hook) for the SvelteKit example's client side. React hook is for the server-side handler test.
   - Recommendation: Use `createDeepAgentsStore` from `@deepagents-nextjs/sveltekit` in the `.svelte` component. Do NOT import from `@deepagents-nextjs/react` in the SvelteKit example's frontend.

3. **Where does `DEBUG=deepagents:sse` demo live in EX-04?**
   - What we know: `shouldDebug()` reads `process.env.DEBUG` (Node.js server-side). It logs to stderr on each SSE frame.
   - What's unclear: EX-04 says "DEBUG=deepagents:sse debug logging toggle" — could mean a UI toggle or just a README note.
   - Recommendation: Implement as README instruction in `packages/server/README.md`. In EX-04 UI, show a visible label that says "Enable: `DEBUG=deepagents:sse`" with copy button. No server-side toggle needed — the handler reads env var automatically.

4. **Does `apps/remix-example` need `@deepagents-nextjs/react` as a dependency?**
   - What we know: `packages/remix/src/hook.ts` exports `useDeepAgentsChat` (Remix-specific, uses React internally). `packages/remix/src/index.ts` does NOT re-export from `@deepagents-nextjs/react`.
   - What's unclear: Remix example's chat UI — does it use `@deepagents-nextjs/remix`'s own `useDeepAgentsChat` or import from `@deepagents-nextjs/react`?
   - Recommendation: Use `useDeepAgentsChat` from `@deepagents-nextjs/remix` only. This is the canonical Remix usage pattern and avoids cross-package imports that the CI guard checks for.
