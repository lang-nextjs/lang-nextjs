# Phase v1.2-03 Plan 02: TypeScript Generics Hook Summary

## What Was Built

Added the `TData` generic parameter to `useDeepAgentsChat`, extending the hook's compile-time type surface to narrow custom `data-*` message variants.

**Types added to `types.ts`:**
- `CustomDataParts<TData>` — mapped type that converts a schema record into a discriminated union of `{ type: K, data: z.infer<TData[K]> }` variants
- `MessageWithCustom<TData>` — conditional type that resolves to `Message` for zero-generic calls and `Message | CustomDataParts<TData>` for parameterized calls

**Hook updated in `hook.ts`:**
- `UseDeepAgentsChatOptions<TData>` gains `schemas?: TData` field
- `UseDeepAgentsChatReturn<TData>` gains `messages: MessageWithCustom<TData>[]`
- `useDeepAgentsChat<TData>` function signature generified; `schemas` passed to `partsToMessages()` third param

**`index.ts`:** re-exports `CustomDataParts` and `MessageWithCustom`

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] @ts-expect-error placement incompatible with Prettier line-wrapping**
- **Found during:** Task 2 GREEN (tsc --noEmit check)
- **Issue:** Plan specified `@ts-expect-error` on a `const _fn = () => useDeepAgentsChat<...>(...)` expression. Prettier wraps the call to the next line, making `@ts-expect-error` suppress the `const` line (no error) rather than the type-error line — producing TS2578 (unused directive) and TS2344 simultaneously
- **Fix:** Replaced runtime call with a pure type-alias: `type _Check = UseDeepAgentsChatReturn<BadTData>` with `@ts-expect-error` on the type alias line — no runtime execution, no Prettier wrapping issue
- **Files modified:** packages/react/src/hook.test.ts
- **Commit:** b82be6d

## Key Decisions

1. **`Record<never, never>` as TData default** — avoids TypeScript empty-object pitfalls; `keyof Record<never, never> extends never` evaluates to `true`, so zero-generic calls get `Message[]` unchanged.

2. **Constraint test uses type alias not runtime call** — calling a hook outside `renderHook` produces "Invalid hook call" at runtime even when wrapped in an arrow function (if Prettier reformats to multi-line, `@ts-expect-error` misses the error line). A type-level test `type _Check = UseDeepAgentsChatReturn<BadTData>` achieves the same compile-time verification with zero runtime risk.

3. **`keyof TData extends never` conditional** — more precise than `TData extends {}` for detecting empty record; prevents `{}` from accidentally matching as non-empty.
