Extend `partsToMessages` in converter.ts to accept an optional third parameter:

```typescript
import type { ZodTypeAny } from 'zod'

export function partsToMessages(
  aiMessages: UIMessage[],
  isStreaming: boolean,
  customSchemaMap?: Record<string, ZodTypeAny>,
): Message[]
```

**Return type stays `Message[]`.** The custom data-* entries are typed as `{ type: string; data: unknown }` at the converter level — the generic type narrowing happens in the hook (Plan 02). Converter is a runtime concern only.

**Implementation change (minimal — only the `data-*` branch):**

In the `else if (partType.startsWith('data-'))` block, replace the current logic with:

```typescript
} else if (partType.startsWith('data-')) {
  flushText()
  const envelope = rawPart as { data?: unknown }

  if (partType === 'data-error') {
    // Existing data-error logic unchanged (keep as-is)
    const parsed = DataErrorSchema.safeParse(envelope.data)
    if (parsed.success) {
      const e = parsed.data
      const err: ErrorMessage = { type: 'error', id: e.id, message: e.message, retryable: e.retryable }
      out.push(err)
    } else {
      console.warn('[partsToMessages] dropped invalid data-error part', parsed.error?.message)
    }
  } else {
    // Check customSchemaMap first; then warn+drop
    const customSchema = customSchemaMap?.[partType]
    if (customSchema) {
      const parsed = customSchema.safeParse(envelope.data)
      if (parsed.success) {
        // Push as a generic data part — hook's return type handles narrowing
        out.push({ type: partType, data: parsed.data } as unknown as Message)
      } else {
        console.warn('[partsToMessages] dropped invalid custom data-* part:', partType, parsed.error?.message)
      }
    } else {
      console.warn('[partsToMessages] dropped unsupported data-* part type:', partType)
    }
  }
}
```

The cast `as unknown as Message` is intentional: at runtime these are valid output entries. The hook's return type (`MessageWithCustom<TData>`) provides the narrowed type — the converter's declared return type `Message[]` is widened at call sites when TData is provided. Add a comment: `// Custom data-* part: runtime push, type narrowed by hook's TData generic`.
