# Phase v1.1-01: Reference Backend Stacks — Context

**Gathered:** 2026-04-29
**Status:** Ready for planning

<domain>
## Phase Boundary

Build two self-contained reference backend stacks for local E2E testing of `deepagents-nextjs`. Both backends use `langchain-ai/deepagents` (`create_deep_agent()`) internally as the AI engine and emit the DeepAgents SSE wire format that `createDeepAgentsHandler` consumes.

**Full design spec:** `docs/superpowers/specs/2026-04-29-reference-backends-design.md`

</domain>

<decisions>
## Implementation Decisions

### Architecture
- Two backend stacks: `apps/django-backend/` (Django 5 + postgres + redis) and `apps/fastapi-backend/` (FastAPI, single container)
- One shared Next.js app: `apps/example/` extended to use `createDeepAgentsHandler({ backendUrl: process.env.BACKEND_URL! })` when `BACKEND_URL` is set
- Existing `MockLanguageModelV3` route preserved as `route.mock.ts` — not deleted
- One shared E2E test suite: `e2e/chat.spec.ts` (Playwright), `BACKEND_URL` selects which backend

### AI Engine
- Both backends use `langchain-ai/deepagents` (`create_deep_agent()`) — LangGraph-based agent
- Real LLM required (ANTHROPIC_API_KEY or OPENAI_API_KEY) — no echo/trivial stub
- Agent config: default `create_deep_agent()` — no custom tools, no custom prompt
- API keys required locally via `.env.local`; injected as GitHub Actions secrets in CI

### SSE Wire Format
Both backends must emit this exact format:
```
data: {"type":"text-start","id":"text-1"}
data: {"type":"text-delta","id":"text-1","delta":"..."}
data: {"type":"text-end","id":"text-1"}
data: {"type":"finish","finishReason":"stop","usage":{"inputTokens":N,"outputTokens":N},"messageId":"msg-<uuid>"}
```
The `messageId` in `finish` is intentional — proves `defaultTransforms` strips it.

### LangGraph → SSE Conversion
Both backends share the same conversion pattern (copy-paste, not a shared lib):
- Use `graph.astream_events({"messages": [...]}, version="v2")`
- Filter `on_chat_model_stream` events for text deltas
- Wrap in DeepAgents SSE envelope

### Docker Compose
- Each backend has its own `docker-compose.yml` (self-contained)
- Django compose: `db` (postgres:16) + `redis` (redis:7-alpine) + `backend` + `frontend` (apps/example)
- FastAPI compose: `backend` + `frontend` (apps/example) only
- Ports: Django backend 8000 / Next.js 3001; FastAPI backend 8001 / Next.js 3002

### CI
- Two jobs: `e2e-django` and `e2e-fastapi`
- Both skip on external PRs (no secret access)
- Both use same `e2e/chat.spec.ts` test suite

### Claude's Discretion
- Exact Django view structure (class-based vs function-based)
- How to handle LangGraph async in Django (asyncio.run vs async view)
- FastAPI lifespan pattern for graph initialization
- Playwright config details (timeouts, retries)
- `.env.local.example` content

</decisions>

<specifics>
## Key Specifics

- `apps/example/route.ts` must remain backward compatible: when `BACKEND_URL` is not set, it should still work (either error clearly or fall back to mock)
- The `messageId` field in the `finish` event is the key E2E signal: present in backend output, absent in client stream
- Do not add LangGraph server or LangServe — plain FastAPI `StreamingResponse` is correct
- Django: use `StreamingHttpResponse` with an async generator; do NOT use Django Channels (overkill)
- Both backends: CORS headers required for Next.js dev server (`localhost:3001`, `localhost:3002`)

</specifics>

<deferred>
## Deferred

- Multi-tenancy implementation in Django backend — this is a minimal reference, not a production clone
- Auth / `getToken` E2E testing — covered by unit tests in `packages/server`
- LangGraph Platform / LangGraph Server integration — V2
- Additional backends (e.g., LangGraph Server backend) — V2, same pattern

</deferred>
