## Decisions Made

- `vitest.config.ts` uses `environment: "node"` not `jsdom` — route.ts handlers are server-side Node code, not browser React components; this differs from apps/example
- `tsconfig.json` intentionally omits `@/* paths` alias — Vitest does not read tsconfig path aliases without explicit `resolve.alias` in vitest.config.ts; all test and implementation files use relative imports
- Stub implementations use synchronous `throw new Error("not implemented")` — this causes immediate runtime failures visible as "not implemented" in test output, not opaque "Cannot find module" errors; Plan 02 replaces these stubs with real implementations
