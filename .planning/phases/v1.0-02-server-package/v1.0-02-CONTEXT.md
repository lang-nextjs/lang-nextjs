<decisions>
## Implementation Decisions

### transforms pipeline composition
- User-provided `transforms?` is **appended after** `defaultTransforms` — the messageId strip always runs unless the user explicitly bypasses it
- `defaultTransforms` is exported as a named export so power users can do full replacement: `createDeepAgentsHandler({ transforms: [...defaultTransforms, myTransform] })`
- This guarantees protocol compliance (SRV-04) out of the box for the two-line setup goal (SRV-01)
- Pipeline signature: `(frame: SseFrame) => SseFrame | null` — null drops the frame

### getToken auth behavior (fail-open)
- `getToken` returns null/undefined → proxy without Authorization header (let backend decide)
- `getToken` throws → propagate the error (do not swallow; consumer is responsible for error handling in getToken)
- `getToken` not provided → forward all client request headers as-is (same as stsfront source)
- `getToken` returns a string → inject as `Authorization: Bearer {token}`, replacing any client-provided Authorization header
- Rationale: handler is a transport layer, not a policy engine; auth enforcement belongs in Next.js middleware

### Header forwarding
- Forward all client request headers except hop-by-hop: `host`, `content-length`, `transfer-encoding`, `connection`
- This matches the stsfront source exactly and is the correct proxy pattern
- Response headers: always set `Content-Type: text/event-stream`, `Cache-Control: no-cache, no-transform`, `X-Accel-Buffering: no`
- Forward `x-vercel-ai-ui-message-stream` from backend response (required by AI SDK v6 client)

### Error handling
- Backend unreachable (fetch throws) → return `new NextResponse('upstream error', { status: 502 })`
- Non-2xx backend response with no body → return `new NextResponse(null, { status: backendResponse.status })`
- Mid-stream error (ReadableStream error) → `controller.error(err)` breaks the stream; log to `console.error`
- Plain text error bodies (not JSON) — matches stsfront source and keeps the error response simple

### SseFrameAccumulator design
- Buffer accumulates raw chunks, splits on `\n\n` (SSE frame boundary)
- Last element after split is kept as pending buffer (incomplete frame)
- On stream done: flush any remaining buffer content
- This is an extraction of the inline buffering logic already in stsfront route.ts

### Claude's Discretion
- Exact TypeScript type names for `SseFrame`, `SseTransform` — follow tsup/TypeScript conventions
- Whether `SseFrameAccumulator` is a class or a function returning closures
- How to structure the `defaultTransforms` array (single transform or multiple)
- Whether to expose a `createSseTransformStream()` helper or keep it internal

</decisions>

<specifics>
## Specific Ideas

- "Port and generalize" is the mandate — don't rewrite from scratch, don't over-engineer
- The stsfront route.ts inline `transformSseFrame` function becomes a named `SseTransform` in `defaultTransforms`
- The inline buffer logic in `ReadableStream.start()` becomes `SseFrameAccumulator`
- The `duplex: 'half'` comment (`@ts-expect-error — Node 18 fetch needs duplex for streaming bodies`) should be preserved as documentation
- Two-line consumer usage is the success bar: `import { createDeepAgentsHandler } from '@deepagents-nextjs/server'` + `export const POST = createDeepAgentsHandler({ backendUrl: process.env.BACKEND_URL })`

</specifics>
