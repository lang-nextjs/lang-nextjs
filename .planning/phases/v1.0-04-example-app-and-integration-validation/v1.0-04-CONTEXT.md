# Phase v1.0-04: Example App and Integration Validation - Context

**Gathered:** 2026-04-29
**Status:** Ready for planning

<domain>
## Phase Boundary

Build a working Next.js example app in `apps/example/` that demonstrates `useDeepAgentsChat()` end-to-end against a mock SSE backend. No real DeepAgents backend is required. The deliverable is a runnable chat UI that proves the library works in a real Next.js App Router context.

Out of scope: real backend integration, authentication, production deployment, Playwright E2E tests, shadcn/radix components.

</domain>

<decisions>
## Implementation Decisions

### Mock SSE Backend Content
- The mock route (`app/api/chat/stream/route.ts`) emits a scripted multi-part response using the AI SDK v6 stream protocol
- Must emit at minimum: text chunks (producing an AIMessage) AND a tool-call sequence (producing a ToolCallMessage) — satisfies EX-01 success criterion 2
- Response must include the `x-vercel-ai-ui-message-stream: v1` header — satisfies EX-01 success criterion 4
- Use `createDataStreamResponse` + `streamText` (or manual protocol bytes) from the `ai` package to produce valid SSE output
- The mock ignores the incoming `sessionId` — it always returns the same scripted exchange
- Chunked output must arrive progressively (no buffering) — satisfies EX-01 success criterion 3

### Chat UI Layout
- Full-page chat layout: message list fills the viewport, input bar pinned to the bottom
- Shows all message types: UserMessage (right-aligned bubble), AIMessage (left-aligned, streaming indicator while isStreaming=true), ToolCallMessage (collapsed card with toolName + status badge)
- Streaming indicator: append `▋` cursor to AIMessage content while isStreaming=true (simple, no animation library needed)
- No ErrorMessage UI needed for the happy-path mock (but type is handled gracefully if it appears)
- Tailwind CSS for styling — already part of Next.js defaults; no shadcn/radix

### App Scaffolding
- Use Next.js App Router (already present as placeholder in `apps/example/`)
- Structure: `app/page.tsx` (client chat UI), `app/api/chat/stream/route.ts` (mock SSE route)
- `'use client'` on the page component (required for `useDeepAgentsChat`)
- No extra pages or routes needed
- Minimal Tailwind classes — reference-quality code, not production polish

### Integration Verification Approach
- No automated E2E (no Playwright) — this phase is about library integration proof, not test coverage
- Verification is manual: `pnpm dev` → browser visual check + `curl -N` SSE output check
- Vitest unit tests are NOT needed for the example app (it's a demo, not a library)
- The VALIDATION.md success criteria from ROADMAP.md are verified by the executor via `curl` output in the SUMMARY

### Claude's Discretion
- Exact Tailwind class choices and spacing
- Whether to add a `<title>` and minimal page metadata
- How to handle the ToolCallMessage card's visual design (badge color, layout)
- Whether `apps/example/` needs its own `tsconfig.json` or inherits from root

</decisions>

<specifics>
## Specific Ideas

- The mock backend should be a clear, well-commented reference implementation — someone reading it should understand exactly how to wire their real DeepAgents backend
- The chat component should be readable in ~100 lines — reference-quality, not production-hardened
- `curl -N http://localhost:3000/api/chat/stream` with a POST body is the primary smoke test; the SUMMARY must include the actual curl output showing chunked SSE lines

</specifics>
