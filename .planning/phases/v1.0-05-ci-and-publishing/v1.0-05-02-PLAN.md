# Plan v1.0-05-02: CI Workflow — PR Gates

## Goal

Create `.github/workflows/ci.yml` that runs `turbo build`, `turbo test`, and the `publint`/`attw` validation gates on every PR and on every push to `main`. Failing gates block merge (enforced via branch protection — manual step documented in verification).

## Context

- Root `package.json` has `packageManager: "pnpm@9.0.0"` — `pnpm/action-setup@v4` reads this automatically
- `turbo.json` defines `build`, `test`, `typecheck` tasks with correct dependency order
- Wave 1 added `validate` script to both packages + `turbo.json` validate task
- No `.github/` directory exists yet

## Tasks

<task id="1">
<title>Create .github/workflows/ci.yml with build, test, and validation gates</title>
<action>
Create `.github/workflows/ci.yml`:

```yaml
name: CI

on:
  pull_request:
    branches: [main]
  push:
    branches: [main]

concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true

jobs:
  ci:
    name: Build, Test, Validate
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Setup pnpm
        uses: pnpm/action-setup@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: pnpm

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Build
        run: pnpm build

      - name: Test
        run: pnpm test

      - name: Typecheck
        run: pnpm typecheck

      - name: Validate packages (publint + attw)
        run: pnpm turbo validate
```

Notes:
- `pnpm/action-setup@v4` reads `packageManager: "pnpm@9.0.0"` from root `package.json` — no version arg needed
- `cancel-in-progress: true` cancels stale PR runs on new push
- `pnpm turbo validate` runs `publint && attw --pack .` for both packages in build-order via Turborepo
- `pnpm build` is a separate step before validate so `dist/` exists for `attw --pack .`

Note on branch protection: After this workflow is active on GitHub, configure branch protection for `main`:
- Required status checks: `Build, Test, Validate` (the job name above)
- Require branches to be up to date before merging
This is a manual step in GitHub repo settings (cannot be automated in the workflow file itself).
