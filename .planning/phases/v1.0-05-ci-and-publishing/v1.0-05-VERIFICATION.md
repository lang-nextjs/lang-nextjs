### SC-3: Running `pnpm changeset publish` from the publish workflow creates a versioned npm release with OIDC provenance (`NPM_CONFIG_PROVENANCE=true`) — no long-lived npm token required

**PASS**

- `.github/workflows/publish.yml` uses `changesets/action@v1` with `publish: pnpm changeset publish`
- `NPM_CONFIG_PROVENANCE: "true"` is set in env block of changesets action
- `permissions: id-token: write` enables OIDC token in runner
- `registry-url: https://registry.npmjs.org` configures npm registry for OIDC exchange
- No `NPM_TOKEN` secret referenced anywhere in the workflow

Evidence: `.github/workflows/publish.yml`

### SC-4: Changesets is configured so that version bumps on `main` do not block the main branch with unresolved prerelease state

**PASS**

- `.changeset/config.json` uses standard release mode (no `prerelease` config)
- `fixed: [["@deepagents-nextjs/server", "@deepagents-nextjs/react"]]` — both packages version together
- `commit: false` — changeset bot creates version PR as a normal PR
- Merge of version PR = publish; no lingering state afterward
- `access: "public"` — scoped packages publish as public

Evidence: `.changeset/config.json`
