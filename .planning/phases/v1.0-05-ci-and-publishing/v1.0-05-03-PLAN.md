# Plan v1.0-05-03: Publish Workflow — Changesets + OIDC Provenance

## Goal

Create `.github/workflows/publish.yml` that implements the Changesets release workflow with OIDC provenance. When a changeset PR is merged to `main`, this workflow publishes both packages to npm with `NPM_CONFIG_PROVENANCE=true` — no long-lived npm token required.

## Context

- Wave 1: `.changeset/config.json` initialized with `fixed` versioning, `access: public`
- Wave 2: `ci.yml` gates PRs with build + test + validate
- This workflow uses `changesets/action@v1` which:
  1. When changesets exist: creates a "Version Packages" PR that bumps `package.json` versions and updates `CHANGELOG.md`
  2. When the version PR is merged: runs `pnpm changeset publish` to publish to npm

## OIDC Provenance Design

GitHub Actions OIDC exchange with npm works as follows:
- `permissions: id-token: write` enables the OIDC token in the runner
- `actions/setup-node@v4` with `registry-url: https://registry.npmjs.org` configures the npm registry
- `NPM_CONFIG_PROVENANCE=true` tells npm to request a provenance attestation during publish
- npm exchanges the GitHub OIDC token for a short-lived publish token (no `NPM_TOKEN` secret required)

**One-time prerequisite (manual):** On npmjs.com, for each package, configure "Trusted Publishers" under package settings to allow the GitHub Actions OIDC token from this repo. This cannot be scripted — it is a one-time manual step per package.

<action>
Create `.github/workflows/publish.yml`:

```yaml
name: Publish

on:
  push:
    branches: [main]

concurrency: ${{ github.workflow }}-${{ github.ref }}

jobs:
  publish:
    name: Release
    runs-on: ubuntu-latest
    permissions:
      contents: write      # create tags and GitHub releases
      id-token: write      # OIDC token for npm provenance
      pull-requests: write # changeset bot creates version PRs

    steps:
      - name: Checkout
        uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Setup pnpm
        uses: pnpm/action-setup@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: pnpm
          registry-url: https://registry.npmjs.org

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Build packages
        run: pnpm build

      - name: Create Release PR or Publish
        uses: changesets/action@v1
        with:
          publish: pnpm changeset publish
          title: "chore: release packages"
          commit: "chore: release packages"
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          NPM_CONFIG_PROVENANCE: "true"
```

Notes:
- `fetch-depth: 0` — Changesets needs full git history to detect which packages changed
- `contents: write` — allows the changeset bot to push version bump commits
- `pull-requests: write` — allows the bot to create/update the version PR
- `id-token: write` — required for OIDC npm provenance
- `registry-url: https://registry.npmjs.org` — configures npm registry for OIDC exchange
- No `NPM_TOKEN` secret — OIDC handles authentication
- `NPM_CONFIG_PROVENANCE: "true"` — npm publishes with provenance attestation
- `pnpm changeset publish` — the command Changesets action calls for the actual publish

### How the workflow operates

**Steady state (changesets exist on main):**
1. Developer runs `pnpm changeset` locally, commits the changeset file to a PR
2. PR merges to main
3. This workflow runs → `changesets/action` detects the changeset → creates/updates a "Version Packages" PR

**On version PR merge:**
1. "Version Packages" PR merges to main (bumps package.json versions, writes CHANGELOG)
2. This workflow runs again → no changesets remain → `changesets/action` publishes to npm
3. Both packages publish atomically (fixed versioning) with provenance

**SC-4 compliance:** Standard release mode (not prerelease) means the version PR is a normal PR — merge it when ready. No lingering prerelease state on main.
