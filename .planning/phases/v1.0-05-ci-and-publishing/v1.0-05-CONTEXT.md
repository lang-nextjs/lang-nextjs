# Phase v1.0-05: CI and Publishing - Context

**Gathered:** 2026-04-29
**Status:** Ready for planning

<domain>
## Phase Boundary

Wire up GitHub Actions CI (PR gates + publish workflow) for both `@deepagents-nextjs/server` and `@deepagents-nextjs/react`. Gates: `publint` + `are-the-types-wrong` (`attw`) on every PR. Publish: OIDC provenance to npm triggered by Changesets version PR merge. The monorepo scaffold and both packages already exist — this phase only adds CI + publishing infrastructure.

</domain>

<decisions>
## Implementation Decisions

### Versioning strategy
- Fixed versioning across both packages — they release together (server + react are coupled)
- Changesets manages version bumps via bot-created version PRs
- No prerelease state that blocks main (SC-4 from ROADMAP)
- Standard Changesets config: `changesets/action` for version + publish

### CI gate placement
- `publint` and `attw --pack .` run on every PR for both packages
- Also run on pushes to main (belt-and-suspenders)
- Gates run inside `turbo build` dependency order (server before react)
- Failing gates block merge — required status checks in branch protection

### npm publish authentication
- OIDC provenance only — `NPM_CONFIG_PROVENANCE=true`
- No long-lived npm token stored in secrets
- GitHub Actions `id-token: write` permission required for OIDC
- npm package access: `public` (scoped packages default to private)

### Publish trigger
- Changesets "version" PR created automatically when changesets land on main
- Merge of version PR triggers publish workflow
- Publish workflow: `turbo build` → `publint`/`attw` validation → `pnpm changeset publish`

### Workflow structure
- Two separate workflow files: `ci.yml` (PR + push gates) and `publish.yml` (triggered on version PR merge)
- Reuse composite action or shared step for the validation gates
- `publish.yml` needs `id-token: write` + `contents: write` permissions for OIDC + tagging

### Claude's Discretion
- Exact Node.js version pinned in CI (use LTS, currently 20.x or 22.x)
- pnpm version pinning strategy
- Cache configuration for turbo/pnpm in CI
- Exact branch protection rule configuration (require reviews vs not)

</decisions>
