## Key Technical Patterns

### 1. Changeset Configuration (`.changeset/config.json`)

```json
{
  "$schema": "https://unpkg.com/@changesets/config@3.0.0/schema.json",
  "changelog": "@changesets/cli/changelog",
  "commit": false,
  "fixed": [["@deepagents-nextjs/server", "@deepagents-nextjs/react"]],
  "linked": [],
  "access": "public",
  "baseBranch": "main",
  "updateInternalDependencies": "patch",
  "ignore": []
}
```

Key choices:
- `fixed` array groups both packages — they always bump together (SC-4: no blocking prerelease)
- `access: "public"` — matches `publishConfig.access` on both packages
- `commit: false` — changeset bot handles commits, not the CLI
- `baseBranch: "main"` — standard

### 2. CI Workflow (`ci.yml`)

Triggers: `pull_request`, `push` to main.

Steps:
1. `actions/checkout@v4`
2. `pnpm/action-setup@v4` (uses `packageManager` field from root package.json for version)
3. `actions/setup-node@v4` with `node-version: 22` and `cache: 'pnpm'`
4. `pnpm install --frozen-lockfile`
5. `pnpm turbo build test typecheck` (or separate steps: `pnpm build`, `pnpm test`)
6. `publint` for each package: `cd packages/server && npx publint` + `cd packages/react && npx publint`
7. `attw` for each package: `cd packages/server && npx @arethetypeswrong/cli --pack .` + `cd packages/react && npx @arethetypeswrong/cli --pack .`

Notes:
- `attw --pack .` packs the local package and checks exports — no npm publish required
- Both `publint` and `@arethetypeswrong/cli` are already in devDeps of each package, so `npx` will use the local version

### 3. Publish Workflow (`publish.yml`)

Triggers: `push` to main (changeset action creates a version PR; when version PR merges, this triggers on main).

Canonical pattern with `changesets/action`:

```yaml
name: Publish
on:
  push:
    branches: [main]

concurrency: ${{ github.workflow }}-${{ github.ref }}

jobs:
  publish:
    name: Publish
    runs-on: ubuntu-latest
    permissions:
      contents: write      # for creating tags + GitHub releases
      id-token: write      # for OIDC provenance
      pull-requests: write # for changeset bot to create version PRs
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: pnpm
          registry-url: https://registry.npmjs.org
      - run: pnpm install --frozen-lockfile
      - run: pnpm build
      - name: Create Release PR or Publish
        uses: changesets/action@v1
        with:
          publish: pnpm changeset publish
          title: "chore: release packages"
          commit: "chore: release packages"
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          NPM_TOKEN: not-used-oidc-handles-auth
          NPM_CONFIG_PROVENANCE: "true"
          NODE_AUTH_TOKEN: ${{ secrets.GITHUB_TOKEN }}  # not for npm — placeholder
```

**Critical OIDC note:** When using OIDC provenance, npm authentication uses the `registry-url` + `NODE_AUTH_TOKEN` combo from `setup-node`. The `NODE_AUTH_TOKEN` must be set to something that triggers the OIDC exchange. In practice for npm OIDC:
- Set `registry-url: https://registry.npmjs.org` in setup-node
- Set `NPM_CONFIG_PROVENANCE: "true"` 
- The package must be published from a trusted GitHub Actions context (GitHub's OIDC exchange with npm)
- No `NPM_TOKEN` secret needed — npm's OIDC trust is configured on the npm package level

**OIDC + Changesets integration caveat:** `changesets/action` supports OIDC as of `@changesets/action@v1.4.0`. The `NPM_CONFIG_PROVENANCE=true` environment variable is the mechanism — `pnpm changeset publish` inherits it and passes it to npm.

### 4. `attw` (`@arethetypeswrong/cli`) usage

```bash
# Pack locally and check — no publish
npx @arethetypeswrong/cli --pack . --format table
```

`--pack .` runs `npm pack` locally and checks the resulting tarball. For CI:
```bash
npx @arethetypeswrong/cli --pack . --format json | node -e "
  const r = JSON.parse(require('fs').readFileSync('/dev/stdin','utf8'));
  if (r.problems && r.problems.length > 0) { console.error(JSON.stringify(r.problems, null, 2)); process.exit(1); }
"
```
Or simply: `npx @arethetypeswrong/cli --pack .` — exits non-zero if any problems found (default behavior).

### 5. pnpm action-setup version resolution

`pnpm/action-setup@v4` can read the pnpm version from `packageManager` field in root `package.json`. Root already has `"packageManager": "pnpm@9.0.0"` — no extra config needed in the workflow.

### 6. Turbo in CI

`pnpm turbo build` respects the `dependsOn: ["^build"]` ordering. In CI, remote caching is not needed for correctness — content-addressed local cache is enough. For speed: Turborepo remote cache can be added later (deferred).

## Risk Flags

1. **OIDC + npm package trust**: OIDC provenance requires the npm package to be configured to allow GitHub Actions OIDC tokens. The `@deepagents-nextjs/server` and `@deepagents-nextjs/react` packages do not yet exist on npm — the first publish must use `--access public` and the package owner must enable OIDC trust on npm's website (or via `npm access grant`). This is a one-time manual step outside CI.

2. **`changesets/action` OIDC support**: Confirmed in `changesets/action@v1` with `NPM_CONFIG_PROVENANCE=true` environment variable. The action calls `pnpm changeset publish` which invokes npm publish with the provenance flag.

3. **No `NPM_TOKEN` secret required**: With OIDC, the `NODE_AUTH_TOKEN` is not an npm API token — the OIDC exchange is handled by the `registry-url` in `setup-node` + GitHub's OIDC provider. The `GITHUB_TOKEN` is still needed for the changeset bot to create PRs.

4. **`attw` local behavior**: `--pack .` runs `npm pack` which requires a built `dist/` directory. CI must run `pnpm build` before running `attw`.
