# Requirements: deepagents-nextjs v1.5

**Defined:** 2026-05-04
**Core Value:** Developers can manage open-swe coding agent runs end-to-end — submitting tasks, watching live output, inspecting tool calls, and automating via MCP — against a local LangGraph Platform server.

---

## Milestone v1.5 Requirements

### Adapter (openSweAdapter)

- [x] **ADAPT-01** — Developer can stream open-swe `on_tool_start` events as AI SDK v6 `tool-input-start` frames from a LangGraph Platform `astream_events v2` run
- [x] **ADAPT-02** — Developer can stream open-swe `on_tool_end` events as AI SDK v6 `tool-output-available` frames from a LangGraph Platform run
- [x] **ADAPT-03** — Long-running open-swe runs (>2 min) do not timeout — adapter emits an SSE heartbeat frame every 15–30 seconds when no events arrive from the upstream
- [x] **ADAPT-04** — Parallel tool calls that arrive out-of-order are buffered and reordered correctly by `tool_call_id` before emission to the client
- [x] **ADAPT-05** — Developer can gate tool execution — adapter emits a `data-approval-required` frame; the run pauses until an explicit approval or rejection is sent back by the handler

### Dashboard (apps/open-swe)

- [x] **DASH-01** — User can submit a coding task description and receive a `run_id` in response from the `POST /api/open-swe/runs` endpoint
- [x] **DASH-02** — User can view a list of all runs with their status (pending/running/completed/failed), creation time, and task description
- [x] **DASH-03** — User can watch a live stream of agent output (text, tool calls) for an active run in real time via `GET /api/open-swe/runs/[runId]/stream`
- [x] **DASH-04** — User can expand a tool call card in the run view to inspect the tool's full input payload and output result
- [x] **DASH-05** — User can view multiple concurrent runs and switch between their live streams without event leakage between streams (concurrent stream isolation)

### MCP Tools (packages/mcp)

- [x] **MCP-01** — LLM agent can trigger a new open-swe coding task via `trigger_task` MCP tool and receive a `run_id` immediately — no waiting for the run to complete
- [x] **MCP-02** — LLM agent can list all open-swe runs and their statuses via `list_runs` MCP tool
- [x] **MCP-03** — LLM agent can retrieve the status and latest output snapshot of a specific run via `get_run_status` MCP tool
- [x] **MCP-04** — LLM agent can request cancellation of an active run via `cancel_run` MCP tool

### E2E / CI (v1.4 fold)

- [x] **E2E-11** — With `ENABLE_STREAM_RECONNECT=true`, a `retry()` call after a simulated mid-stream network interruption resumes the stream and appends new content without duplicating already-received messages
- [x] **CI-01** — A `pnpm test:e2e` script runs the full Playwright E2E suite against a locally-started Next.js dev server in a single command; a GitHub Actions job runs this suite on every PR

## Future Requirements (deferred)

- **ADAPT-06** — Blazing sandbox integration — openSweAdapter routes shell execution events through blazing API (deferred; test locally first)
- **DASH-06** — Unified diff viewer — open-swe file changes rendered as a GitHub-style inline diff in the run view
- **MCP-05** — Webhook/SSE-based run notifications — LLM agent subscribes to run updates instead of polling (deferred pending MCP resource subscriptions spec #491)
- **INFRA-01** — Multi-region task context — handler maintains task context across region failover during a run

---

## Out of Scope

- **WebSocket transport** — SSE is the DeepAgents protocol; no WebSocket upgrade path
- **Manual approval every tool call** — approval gating is opt-in per handler; default is pass-through
- **Real-time unified view across all runs** — each run has its own isolated stream endpoint; no aggregated real-time feed
- **open-swe backend itself** — this project wraps the open-swe LangGraph agent; it does not ship the agent code
- **Blazing integration** — deferred; test locally against LangGraph Platform server only in v1.5
