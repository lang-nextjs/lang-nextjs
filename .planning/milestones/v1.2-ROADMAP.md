## Phase Details

### Phase v1.2-01: Backend Adapter API + Retry Policy
**Goal**: Consumers can pass named adapter bundles to `createDeepAgentsHandler` and configure retry policy, with zero breaking changes to existing call sites
**Depends on**: Nothing (extends existing server package)
**Requirements**: ADAPT-01, ADAPT-02, ADAPT-03, ADAPT-04, STR-02
**Success Criteria** (what must be TRUE):
  1. Existing `createDeepAgentsHandler({ backendUrl })` call sites continue to work unchanged — `deepagentsAdapter` applies automatically as the default
  2. Consumer can pass `adapter: langGraphAdapter` and raw LangGraph `astream_events v2` frames are normalized to AI SDK v6 wire format without any custom transforms (requires pre-work: trace real LangGraph SSE frame shapes before implementation)
  3. Consumer can pass `adapter: langchainAdapter` and raw LangChain native SSE frames are normalized to AI SDK v6 wire format (requires pre-work: trace real LangChain SSE frame shapes before implementation)
  4. `createDeepAgentsHandler({ backendUrl, retry: { maxRetries: 3, initialDelayMs: 100 } })` retries on backend connection failure with exponential backoff; mid-stream failures are not retried
  5. `defaultTransforms` remains importable but is marked `@deprecated` in JSDoc — no runtime removal
**Plans**: 4 plans
Plans:
- [ ] v1.2-01-01-PLAN.md — Capture LangGraph + LangChain SSE frame fixtures from live backends
- [ ] v1.2-01-02-PLAN.md — Adapter infrastructure (SseAdapter type, deepagentsAdapter, handler extension, retry logic, deprecated alias, exports)
- [ ] v1.2-01-03-PLAN.md — langGraphAdapter TDD (astream_events v2 → AI SDK v6)
- [ ] v1.2-01-04-PLAN.md — langchainAdapter TDD (LangChain native SSE → AI SDK v6)

### Phase v1.2-02: DX Tools + Auth Helper
**Goal**: Developers can diagnose SSE issues via debug logging, spin up a mock backend in test suites, and read cookie tokens without boilerplate
**Depends on**: Phase v1.2-01
**Requirements**: DX-01, DX-02, AUTH-01
**Success Criteria** (what must be TRUE):
  1. Setting `DEBUG=deepagents:sse` before starting the Next.js dev server causes parsed SSE frames to appear on stderr; no output when the env var is absent
  2. A consumer test file can `import { createMockDeepAgentsServer } from '@deepagents-nextjs/test-utils'`, start it, run a fetch against it, and assert on typed messages — without any real backend
  3. `getCookieToken('session')` used as the `getToken` option injects the `session` cookie value as a Bearer token; passing no cookie name returns no Authorization header
**Plans**: 2 plans
Plans:
- [ ] v1.2-02-01-PLAN.md — TDD: debug logging (DX-01) + getCookieToken auth helper (AUTH-01) in server package
- [ ] v1.2-02-02-PLAN.md — TDD: @deepagents-nextjs/test-utils package with createMockDeepAgentsServer (DX-02)

### Phase v1.2-03: TypeScript Generics
**Goal**: The React hook accepts a generic type parameter so consumers get compile-time inference for custom `data-*` message schemas
**Depends on**: Phase v1.2-02
**Requirements**: DX-03
**Success Criteria** (what must be TRUE):
  1. `useDeepAgentsChat<{ 'data-plan': typeof PlanSchema }>({ sessionId, endpoint })` narrows `data-plan` message types to the provided schema at compile time with no runtime cost
  2. `useDeepAgentsChat({ sessionId, endpoint })` (zero-generic call) produces identical TypeScript types to the v1.1 hook — no regression for existing consumers
  3. TypeScript compiler rejects a `TData` value that does not extend `Record<string, ZodTypeAny>`
**Plans**: 2 plans
Plans:
- [ ] v1.2-03-01-PLAN.md — TDD: extend partsToMessages with optional customSchemaMap for custom data-* runtime parsing
- [ ] v1.2-03-02-PLAN.md — TDD: useDeepAgentsChat<TData> generic hook signature, CustomDataParts type, zero-generic compat

### Phase v1.2-04: SvelteKit Adapter
**Goal**: SvelteKit developers can wire DeepAgents end-to-end using a handler for `RequestEvent` and a Svelte reactive store, Node runtime only
**Depends on**: Phase v1.2-01
**Requirements**: FWK-01
**Success Criteria** (what must be TRUE):
  1. A SvelteKit `+server.ts` route can call `createDeepAgentsHandler(event, { backendUrl })` and return the result — SSE streams correctly to the SvelteKit client
  2. The Svelte reactive store exposes `messages`, `status`, and `error` that update reactively as SSE frames arrive — usable directly in Svelte component markup
  3. `@deepagents-nextjs/sveltekit` passes `publint` and `attw` in CI; its `peerDependencies` list `@sveltejs/kit` and do not pull in `@deepagents-nextjs/react`
  4. Package fails with a clear error message if run in a non-Node runtime (e.g., Cloudflare Workers)
**Plans**: 4 plans
Plans:
- [ ] v1.2-04-01-PLAN.md — Package scaffold (package.json, tsconfig, tsup, vitest) + accumulator copy + types/stubs
- [ ] v1.2-04-02-PLAN.md — TDD: createDeepAgentsHandler (RequestEvent proxy, transform pipeline, runtime guard)
- [ ] v1.2-04-03-PLAN.md — TDD: createDeepAgentsStore (writable store, StartStopNotifier, SSE parse loop)
- [ ] v1.2-04-04-PLAN.md — Build + publint/attw validation + CI pipeline integration

### Phase v1.2-05: Remix Adapter + Conditional Stream Reconnection
**Goal**: Remix developers can wire DeepAgents end-to-end using a handler for `ActionFunctionArgs` and a React hook with native fetch streaming; STR-01 deferred to v1.3 (AI SDK bugs #6502 and #9707 confirmed open 2026-05-02)
**Depends on**: Phase v1.2-01
**Requirements**: FWK-02, STR-01 (conditional — include only if AI SDK bugs #6502 and #9707 are resolved before this phase closes)
**Success Criteria** (what must be TRUE):
  1. A Remix action function can call `createDeepAgentsHandler(args, { backendUrl })` and return the result — SSE streams correctly to the Remix client
  2. `useDeepAgentsChat` exposes the same `messages`, `status`, `error` surface as the Next.js hook (uses native fetch + ReadableStream loop, NOT useFetcher.data — useFetcher cannot stream SSE)
  3. `@deepagents-nextjs/remix` passes `publint` and `attw` in CI; its `peerDependencies` list `@remix-run/react` and do not pull in `@deepagents-nextjs/react`
  4. *(Conditional — STR-01)* If AI SDK bugs #6502 and #9707 are resolved: `useDeepAgentsChat` resumes an interrupted stream via `experimental_resume` without re-sending the user message. If not resolved: this criterion is deferred to v1.3.
**Plans**: 4 plans
Plans:
- [ ] v1.2-05-01-PLAN.md — Package scaffold (package.json, tsconfig, tsup, vitest) + accumulator copy + types/stubs
- [ ] v1.2-05-02-PLAN.md — TDD: createDeepAgentsHandler (ActionFunctionArgs proxy, transform pipeline, runtime guard)
- [ ] v1.2-05-03-PLAN.md — TDD: useDeepAgentsChat React hook (useState + fetch ReadableStream loop, status transitions)
- [ ] v1.2-05-04-PLAN.md — Build + publint/attw validation + targeted CI guard (handler dist only, not hook)
