# Roadmap: deepagents-nextjs

## Overview

The project ships two scoped npm packages — `@deepagents-nextjs/server` and `@deepagents-nextjs/react` — inside a pnpm monorepo. Delivery flows in one strict dependency chain: the monorepo scaffold must exist before either package, the server package must be correct before the React hook can be validated, both packages must be stable before the example app can serve as the integration surface, and the integration surface must pass all gates before anything is published to npm. Five phases, each a coherent deliverable that unlocks the next.

**Phase Numbering:** Milestone-scoped (v1.0-NN), resetting to 01 each milestone.

### Phase v1.0-02: Server Package
**Goal**: A Next.js developer can drop `createDeepAgentsHandler()` into a route handler and have a correctly streaming, protocol-compliant SSE proxy with known Django mismatches already stripped
**Depends on**: Phase v1.0-01
**Requirements**: SRV-01, SRV-02, SRV-03, SRV-04, SRV-05, SRV-06
**Source material** (port and generalize — do not rewrite from scratch):
- `/Users/jonathanborduas/code/stsfront/next-app/app/api/chat/stream/route.ts` — SSE proxy + `transformSseFrame()` + `messageId` strip logic → becomes `createDeepAgentsHandler` + `defaultTransforms` + `SseFrameAccumulator`
**Success Criteria** (what must be TRUE):
  1. Calling `createDeepAgentsHandler({ backendUrl })` in `route.ts` returns a POST handler in one line with no additional wiring
  2. SSE frames from a mock Django backend arrive at the client progressively — `curl -N` shows chunks, not a buffered dump
  3. A `finish` event containing `messageId` is silently stripped by `defaultTransforms` before the client sees it
  4. A frame artificially split across two TCP chunks is reassembled correctly by `SseFrameAccumulator` — no corruption, no dropped event
  5. When the backend is unreachable the handler returns HTTP 502; on a mid-stream error it returns HTTP 500

**Depends on**: Phase v1.0-03

**Success Criteria** (what must be TRUE):

  4. The `x-vercel-ai-ui-message-stream: v1` header is present in the route's response headers

## Milestone v1.1: Reference Backend Stacks

### Phase v1.1-01: Reference Backend Stacks
**Goal**: A developer can `docker compose up` in either `apps/django-backend/` or `apps/fastapi-backend/` and run the shared E2E suite against both, proving `createDeepAgentsHandler` is backend-agnostic across Django and FastAPI
**Depends on**: Phase v1.0-05
**Requirements**: E2E-01, E2E-02, E2E-03, E2E-04, E2E-05
**Design spec**: `docs/superpowers/specs/2026-04-29-reference-backends-design.md`
**Success Criteria** (what must be TRUE):
  1. `docker compose up` in `apps/django-backend/` starts Django + postgres + redis + Next.js frontend; `docker compose up` in `apps/fastapi-backend/` starts FastAPI + Next.js frontend — both reach healthy state with no manual setup beyond copying `.env.local.example`
  2. Both backends emit the DeepAgents SSE wire format: `text-start` → `text-delta` (streamed) → `text-end` → `finish` with `messageId` field present
  3. The shared Playwright E2E suite passes against both backends: SSE delivery confirmed, `finish` frame has no `messageId` on the client side (proves `defaultTransforms` ran), stream closes cleanly
  4. `apps/example/` uses `createDeepAgentsHandler({ backendUrl: process.env.BACKEND_URL! })` when `BACKEND_URL` is set — same Next.js consumer code works against both backends with zero changes
  5. CI runs `e2e-django` and `e2e-fastapi` jobs independently; both pass
