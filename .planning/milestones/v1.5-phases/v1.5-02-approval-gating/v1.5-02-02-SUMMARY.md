## What Was Built

### approval-registry.ts
- `PendingApproval` interface: approvalId, toolCallId, toolName, input, createdAt (ISO string), expiresAt (number ms), bufferedFrames, status (waiting/approved/rejected/timeout)
- `registerApproval` — set in Map by approvalId
- `getApproval` — lazy TTL check: sets status="timeout" if expired and waiting; always returns record (no delete)
- `resolveApproval` — idempotent: no-op if status !== "waiting"
- `cleanupApproval` — delete from registry
- `cleanupExpiredApprovals` — removes ALL expired entries regardless of status (QUORUM-4 stale-approved GC)
- globalThis singleton for HMR stability (mirrors stream-registry.ts pattern)

### adapters/approvalGating.ts
- `createApprovalGatingTransform(config: ApprovalGatingConfig): SseTransform`
- `ApprovalGatingConfig.getApprovalConfig` — per-tool approval routing callback
- [QUORUM-2] Global pause: `pendingApprovalsByToolCallId.size > 0` buffers ALL non-tool frames into `globalBufferedFrames`
- [QUORUM-3] Rejection: emits `{ type: "data-error", data: { code: "approval_rejected", message: ... } }` (not null)
- [QUORUM-4] Cleanup-after-drain: `cleanupApproval()` called after last buffered frame returned via `shiftFromReadyQueue` when `remainingDrainCount === 0`
- Proactive drain check: iterates pending approvals on each transform call to detect externally-resolved approvals (handles the case where `resolveApproval()` is called without further tool-keyed frames)
- readyQueue drain at top of each call (single-frame-per-call contract, mirrors openSwe.ts)
- timeout status: emits `data-error` with `approval_timeout` code

### handler.ts
- `approvalGating?: ApprovalGatingConfig` added to `DeepAgentsHandlerOptions`
- `createApprovalGatingTransform` injected after adapter transforms, before user transforms
- `cleanupExpiredApprovals()` called in finally block when approvalGating is set

### Implementation Deviations

**Proactive drain check added (not in original plan logic):**
The plan's step 7 only drains when a tool-keyed frame arrives for a pending toolCallId. Added `proactiveDrainCheck()` helper called before step 4.
