    **Exported function signature:**
    ```typescript
    import { NextRequest, NextResponse } from "next/server";

    export function createApprovalRoutes(): {
      GET: (
        request: NextRequest,
        context: { params: Promise<{ approvalId: string }> }
      ) => Promise<NextResponse>;
      POST: (
        request: NextRequest,
        context: { params: Promise<{ approvalId: string }> }
      ) => Promise<NextResponse>;
    };
    ```

    Note: Next.js 15 uses `Promise<{ params }>` for dynamic route segments. Use `const { approvalId } = await context.params;` pattern.

    **GET handler — query approval status:**
    ```typescript
    GET: async (request, context) => {
      const { approvalId } = await context.params;
      const approval = getApproval(approvalId);
      if (!approval) {
        return NextResponse.json(
          { error: "approval not found" },
          { status: 404 }
        );
      }
      return NextResponse.json({
        id: approval.approvalId,
        toolCallId: approval.toolCallId,
        toolName: approval.toolName,
        status: approval.status,
        createdAt: approval.createdAt,
        expiresAt: approval.expiresAt,
      });
    }
    ```

    **POST handler — submit decision (approve or reject):**
    ```typescript
    POST: async (request, context) => {
      const { approvalId } = await context.params;

      let body: { decision?: unknown };
      try {
        body = await request.json();
      } catch {
        return NextResponse.json(
          { error: "invalid JSON body" },
          { status: 400 }
        );
      }

      const decision = body.decision;
      if (decision !== "approve" && decision !== "reject") {
        return NextResponse.json(
          { error: "decision must be 'approve' or 'reject'" },
          { status: 400 }
        );
      }

      const approval = getApproval(approvalId);
      if (!approval) {
        return NextResponse.json(
          { error: "approval not found or expired" },
          { status: 404 }
        );
      }

      if (approval.status !== "waiting") {
        return NextResponse.json(
          { error: "approval already resolved", status: approval.status },
          { status: 409 }
        );
      }

      // Resolve: update status in registry. The approvalGating transform reads
      // the status on its next frame call and handles:
      //   - "approved": drains bufferedFrames → calls cleanupApproval() after drain
      //   - "rejected": emits data-error frame → entry is eventually GC'd by cleanupExpiredApprovals()
      //
      // [QUORUM-1] CRITICAL: Do NOT call cleanupApproval(approvalId) here.
      // The SSE transform reads getApproval(approvalId) on its next frame call to detect
      // the resolved status and drain bufferedFrames. If cleanupApproval() is called before
      // that next frame arrives, getApproval() returns undefined and buffered frames are
      // silently lost. Cleanup is the transform's responsibility (after drain), and the
      // handler finally block's cleanupExpiredApprovals() handles eventual GC of any
      // abandoned entries.
      resolveApproval(approvalId, decision as "approve" | "reject");

      return NextResponse.json({ id: approvalId, decision, accepted: true });
    }
    ```

    **Imports:**
    ```typescript
    import { getApproval, resolveApproval } from "./approval-registry";
    ```

    Note: `cleanupApproval` is intentionally NOT imported here. The transform handles cleanup after drain.

    **Rejection flow explanation (for JSDoc):** When `decision === "reject"`, `resolveApproval` sets status to "rejected". On the next frame for that toolCallId, the approvalGating transform detects `approval.status === "rejected"` and returns a `data-error` frame with code="approval_rejected". The pendingApprovalsByToolCallId entry is then cleared in the transform. Eventually cleanupExpiredApprovals() (called in the handler's finally block) will GC the registry entry once it is past TTL.

    Write the factory as a function (not a constant) — allows easy mocking in tests if needed.

    ```markdown
    ## Approval Gating (ADAPT-05)

    Gate tool execution behind explicit human approval. When enabled, the handler emits a
    `data-approval-required` frame and pauses the stream until the client sends an approve
    or reject decision.

    ### Handler setup

    ```typescript
    import { createDeepAgentsHandler } from '@deepagents-nextjs/server'

    export const POST = createDeepAgentsHandler({
      backendUrl: process.env.BACKEND_URL!,
      approvalGating: {
        getApprovalConfig: (toolCall) => {
          // Return { require: true } to gate this tool, or undefined to pass through
          return { require: true, timeoutMs: 300_000 }
        },
      },
    })
    ```

    ### Approval endpoint

    Add a dynamic route at `app/api/approval/[approvalId]/route.ts`:

    ```typescript
    import { createApprovalRoutes } from '@deepagents-nextjs/server'

    const { GET, POST } = createApprovalRoutes()
    export { GET, POST }
    ```

    The client sends a POST request to approve or reject:

    ```typescript
    // Approve
    await fetch(`/api/approval/${approvalId}`, {
      method: 'POST',
      body: JSON.stringify({ decision: 'approve' }),
      headers: { 'Content-Type': 'application/json' },
    })

    // Reject
    await fetch(`/api/approval/${approvalId}`, {
      method: 'POST',
      body: JSON.stringify({ decision: 'reject' }),
      headers: { 'Content-Type': 'application/json' },
    })
    ```

    ### Frame format

    When approval is required, the client receives:

    ```
    data: {"type":"data-approval-required","data":{"id":"<uuid>","seq":0,"actionName":"bash_execute","description":"Approval required for bash_execute","arguments":{"command":"echo hi"},"status":"waiting","createdAt":"2026-05-04T...","expiresAt":"2026-05-04T..."}}
    ```

    This frame matches the `ApprovalSchema` from `@deepagents-nextjs/react`.

    When a rejection is sent, the stream emits a terminal `data-error` frame:

    ```
    data: {"type":"data-error","data":{"code":"approval_rejected","message":"Tool execution was rejected"}}
    ```

    ### Pause behavior

    While any approval is pending, ALL frames (including text-delta frames emitted concurrently
    by the LLM) are buffered and held until the approval resolves. This ensures no partial
    output reaches the client while a tool decision is outstanding.

    ### Default behavior (disabled)

    When `approvalGating` is not set on the handler, the adapter behaves identically to
    the non-gating path — no `data-approval-required` frames are emitted. This is a
    non-breaking addition.
    ```
