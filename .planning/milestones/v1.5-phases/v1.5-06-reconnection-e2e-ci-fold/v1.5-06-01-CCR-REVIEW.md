## Detailed Findings

### Success Criterion 1: pnpm test:e2e from monorepo root runs full Playwright suite including reconnection

**Status:** PARTIAL ✓ / INCOMPLETE ✗

**Evaluation:**

The plan correctly structures Playwright to discover all 6 spec files (nextjs.spec.ts, nextjs-extra.spec.ts, reconnect.spec.ts, remix.spec.ts, sveltekit.spec.ts, and the new open-swe.spec.ts) via projects and testMatch patterns.

**What the plan does right:**
- Adds `open-swe` project with `baseURL: 'http://localhost:3001'` and `testMatch: /open-swe\.spec\.ts/`
- Restricts chromium project testMatch to only `[/nextjs\.spec\.ts/, /nextjs-extra\.spec\.ts/, /reconnect\.spec\.ts/]`
- Removes open-swe.spec.ts from chromium testMatch (self-corrects mid-document, good catch)
- Explicit testMatch prevents open-swe tests from accidentally running against port 3000

**Critical Gap:**
The plan **does not address the `chat.spec.ts` file** in the current repository. The existing e2e directory contains 6 spec files:
1. nextjs.spec.ts
2. nextjs-extra.spec.ts
3. reconnect.spec.ts
4. remix.spec.ts
5. sveltekit.spec.ts
6. **chat.spec.ts** ← NOT MENTIONED IN PLAN

Currently, the GitHub Actions e2e.yml explicitly runs:
```yaml
pnpm test:e2e e2e/nextjs.spec.ts e2e/nextjs-extra.spec.ts e2e/remix.spec.ts e2e/sveltekit.spec.ts e2e/reconnect.spec.ts
```

It **excludes** `chat.spec.ts`. The plan does not explain:
- Whether chat.spec.ts should be included in the full suite
- What chat.spec.ts tests
- Why the chromium project testMatch does not mention it
- Whether running `pnpm test:e2e` (no args) will pick up chat.spec.ts unintentionally

**Issue:** If the chromium testMatch is `[/nextjs\.spec\.ts/, /nextjs-extra\.spec\.ts/, /reconnect\.spec\.ts/]`, then `pnpm test:e2e` will ONLY run those 3 files + the project-specific files (remix.spec.ts on remix project, sveltekit.spec.ts on sveltekit project, open-swe.spec.ts on open-swe project). The glob pattern in testMatch is **inclusive, not additive** — it restricts what matches, not what gets added. This means:

Running `pnpm test:e2e` with the proposed config would run:
- Chromium: nextjs.spec.ts, nextjs-extra.spec.ts, reconnect.spec.ts (per testMatch)
- Remix: remix.spec.ts (per testMatch)
- SvelteKit: sveltekit.spec.ts (per testMatch)
- Open-SWE: open-swe.spec.ts (per testMatch)

chat.spec.ts would NOT run unless it matches chromium testMatch OR the plan explicitly adds it to one of the testMatch patterns. The plan is silent on this.

**Blocking Status:** YES — The plan does not specify how chat.spec.ts is handled in the unified suite.

## Secondary Issues

### Issue 1: Assumption about open-swe server availability

**Location:** Entire task sequence, especially Task 1 verification

The plan verification step says:
```
Run: pnpm exec playwright test --list
Expected: chromium project shows nextjs.spec.ts, nextjs-extra.spec.ts, reconnect.spec.ts (NOT open-swe.spec.ts). open-swe project shows open-swe.spec.ts.
```

This is correct. But then Task 2 verification says:
```
Run (with open-swe dev server running on port 3001): PLAYWRIGHT_OPENSWE_URL=http://localhost:3001 pnpm test:e2e --project=open-swe
Expected: All open-swe spec tests pass (mocked SSE responses, no real LangGraph Platform required).
```

The phrase "with open-swe dev server running on port 3001" is a manual prerequisite, not something the plan causes to happen in CI. This is acceptable for local testing, but the CI failure is not addressed.

**Recommendation:** Add instructions to start the open-swe server in CI (`.github/workflows/e2e.yml`).

### Issue 2: chat.spec.ts ambiguity in testMatch

**Location:** Task 1 description, chromium testMatch list

The plan says:
```
testMatch: [/nextjs\.spec\.ts/, /nextjs-extra\.spec\.ts/, /reconnect\.spec\.ts/]
```

This pattern **explicitly excludes chat.spec.ts**. The existing CI workflow also excludes chat.spec.ts:
```yaml
pnpm test:e2e e2e/nextjs.spec.ts e2e/nextjs-extra.spec.ts e2e/remix.spec.ts e2e/sveltekit.spec.ts e2e/reconnect.spec.ts
```

However, the plan does not document WHY chat.spec.ts is excluded. Is it:
- Deprecated and should be deleted?
- Skipped intentionally (and should be removed from the repo)?
- Awaiting a future phase?
- A mistake in the plan?

The lack of clarity creates risk: if someone runs the full suite locally and gets different tests than CI, they will be confused.

**Recommendation:** Explicitly state in the plan whether chat.spec.ts should be included in the unified suite or removed from the repository. If keeping it, add it to chromium testMatch. If removing it, add a note that v1.5-06 does not cover chat.spec.ts cleanup (defer to future phase).

### Issue 3: PLAYWRIGHT_OPENSWE_URL environment variable

**Location:** playwright.config.ts proposed configuration

The plan includes:
```typescript
{
  name: 'open-swe',
  use: {
    ...devices['Desktop Chrome'],
    baseURL: process.env.PLAYWRIGHT_OPENSWE_URL ?? 'http://localhost:3001',
  },
  testMatch: /open-swe\.spec\.ts/,
}
```

This uses `PLAYWRIGHT_OPENSWE_URL` as an environment variable override. However:
1. CI workflows typically define all env vars explicitly (not silently default)
2. The pattern differs from other projects (PLAYWRIGHT_REMIX_URL, PLAYWRIGHT_SVELTEKIT_URL in the actual playwright.config.ts)
3. No mention of where CI should set this env var

**Recommendation:** Either use the default and document it, or add explicit CI env var setting in `.github/workflows/e2e.yml` (which is not included in the plan).

1. **Critical gap:** .github/workflows/e2e.yml is not updated. CI will not start the open-swe server on port 3001. The playwright open-swe project will fail to connect, causing test failures. This violates success criterion 3 (CI fold).

- Add .github/workflows/e2e.yml to files_modified with full instructions for starting open-swe server and updating the wait loop
