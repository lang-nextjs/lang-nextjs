## What Was Built

### openSwe.ts — 193 lines

Implementation of `createOpenSweTransform()` and `openSweAdapter`:

**Closure state (per request, fresh from getter):**
- `toolCallCounters`: `Map<run_id, Map<toolName, count>>` — generates deterministic toolCallIds in format `${run_id}--${toolName}-N`
- `pendingToolCallIds`: `Map<queueKey, string[]>` — LIFO stack of toolCallIds per `(run_id, toolName)` pair; push on start, pop on end
- `startOrder`: ordered list of all started toolCallIds (head = oldest unfinished); drives reorder buffer
- `endBuffer`: map of buffered end frames keyed by toolCallId, awaiting predecessor completion
- `readyQueue`: overflow queue for drain; satisfies single-frame-per-call SseTransform contract

**Event handling:**
- `on_tool_start` → `tool-input-start` with `{type, toolCallId, toolName, input}` (exact field set)
- `on_tool_end` → `tool-output-available` with `{type, toolCallId, output}` (LIFO pop + reorder buffer check)
- `on_chat_model_stream` → `text-delta` (inherited from langGraphAdapter)
- Pass-through: non-data lines, `[DONE]`, non-JSON, JSON without `event` field
- Drop: all other event types

**Reorder buffer logic:**
1. On `on_tool_end`: LIFO pop → `toolCallId`. If `startOrder[0] === toolCallId` → emit + drain buffer. Otherwise → buffer in `endBuffer`.
2. Drain loop: while `startOrder[0]` is in `endBuffer`, pop and collect frame.
3. If drain yields multiple frames: return first, push rest into `readyQueue`.
4. Next transform call: if `readyQueue` non-empty, return from it (single-frame-per-call contract).

**Adapter:**
```typescript
export const openSweAdapter: SseAdapter = {
  name: "open-swe",
  get transforms(): SseTransform[] {
    return [createOpenSweTransform()];
  },
} as const;
```

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] LIFO pop() instead of plan-specified FIFO shift() for pendingToolCallIds**

- **Found during:** Task 1 — first test run showed 2 failures in reorder-buffer and FIFO-pairing tests
- **Issue 1:** FIFO shift() paired the first arriving same-tool end to toolCallId `-0` (head of startOrder), which emitted immediately. The test expected `null` (buffered). LIFO pop() pairs the most-recently-started call first, so when ends arrive reversed for same-tool, the LIFO gives `-1` (not at head) → buffers correctly.
- **Issue 2:** The plan's join-frames-with-\n\n approach for multi-frame drain caused `JSON.parse(endA.raw.slice(6))` to fail with "Unexpected non-whitespace character after JSON". The test directly parses the returned frame's raw. Fix: return only the first unblocked frame, push extras into `readyQueue` for the next transform call.
- **Fix:** Changed `pendingToolCallIds.get(queueKey)?.shift()` to `.pop()`. Added `readyQueue: SseFrame[]` to closure. On drain: push extras to `readyQueue` instead of joining with `\n\n`.

## Key Decisions Locked In

1. **LIFO pop() for same-tool end pairing:** The plan specified FIFO shift(), but the RED tests from plan 01 require reversed-arrival ends for same-tool calls to be buffered (return null) until the predecessor end arrives. LIFO pop() satisfies both the same-tool reversed test AND the different-tools out-of-order reorder buffer test. The plan's FIFO assumption was incorrect for same-tool parallel calls.

2. **readyQueue for single-frame-per-call contract:** `SseTransform = (frame: SseFrame) => SseFrame | null` — one frame per call. When drain unblocks multiple buffered frames simultaneously, extras go into `readyQueue`. Next transform call returns from readyQueue first. This satisfies both the direct JSON.parse assertion in the reorder buffer test and the FIFO queue pairing test's flush trigger step.

3. **Pre-existing TS2578 not fixed:** `stream-registry.test.ts` has a pre-existing unused `@ts-expect-error` (TS2578). Not caused by this plan's changes; out of scope per deviation rules.
